状态：代码 + 单测完成，待部署生产（2026-11-07）

| 能力 | 文件 | 作用 | 参数 |
| --- | --- | --- | --- |
| `web_batch` | `packages/server/src/capabilities/capabilities/web-batch.ts` | 一次抓取 1–5 个链接，逐个容错 | `urls`(逗号或换行分隔), `maxChars`(默认 4000/上限 12000), `totalChars`(默认 12000/上限 30000) |

执行器白名单 `packages/worker/tool-loop.mjs` 的 `CAPABILITIES` 已同步为 17 个能力。

## 2. 为什么做这三个（对 17 个员工的价值）

- **web_batch**：调研类员工（全网搜索/竞品对标）原来只能一个个 `web_extract`，每轮一步，8–10 步内抓不了几个站；现在一次最多 5 个链接。
- **doc_write**：原来只能产出 markdown 文本，客户要的「排期表 / 预算表 / 方案 Word」拿不到；现在可直接给 xlsx/docx 并落到工作区、返回 OSS 公链。
- **media_process**：混剪/数字人链路的下游需求（把长视频裁 15 秒、抽音轨、压到能发微信的大小、生成封面图）原来完全没有工具。
- **file_delete**：工作区文件只能增不能删，用户资料库会越堆越乱。

## 3. 设计取舍

- **PDF 不做**：服务器没有中文字体包，`pdf-lib` 输出中文会乱码；硬做需要内置 10MB 级 CJK 字体，收益不如让用户拿 docx。`format=pdf` 直接抛「暂不支持 PDF」。
- **web_batch 不并发**：仍是串行抓取（一次 5 个链接约 15–25 秒），避免被目标站判定爬虫；预算耗尽后剩余链接标记「已达总字数上限，未抓取」而不是静默丢弃。
- **media_process 不用 shell**：`spawn` 传参数数组，文件名里带空格/引号也不会注入；输入 ≤200MB、输出 ≤120MB、单次 300 秒超时；远程 URL 走 `pickPublicAddress` SSRF 守卫（T-34 那套）。
- **输出统一走 `saveWorkspaceFile`**：`files.ts` 的 `UPLOAD_ONLY_EXTS` 补了 `.webm`/`.gif`，因此 media 不需要自己写一份落盘逻辑（子 Agent 原本加的 20 行兜底已删除）。

## 5. 环境依赖

- 服务器需 ffmpeg/ffprobe：生产 47.85.46.165 已 `apt-get install ffmpeg`（6.1.1-3ubuntu5，`/usr/bin/ffmpeg`）；本机是 winget 9.0.1，跑单测时用 `FFMPEG_PATH`/`FFPROBE_PATH` 指过去。
- 新增 npm 依赖：`docx@9.5.1`、`pdf-lib@1.17.1`（已写进 `packages/server/package.json`，生产已装）。

## 6. 还没做

- 员工派活/编排（员工 A 调用员工 B）、cron 定时工具、图片/音视频理解、长期记忆检索。
- `doc_write` 只支持 markdown 子集的排版，不支持图片嵌入与自定义样式。
