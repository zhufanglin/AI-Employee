# P32 平台评论回复（本机 RPA）

> 用户需求（m14357）：「平台取数解析……评论回复，以及把「定时发布」扩到多平台一键分发：按你的节奏来就行」
> 本文档覆盖「评论回复」部分。P30（取数结构化）见 `docs/handoff/P30-平台取数结构化.md`，P31（多平台分发）见 `docs/handoff/P31-定时多平台分发.md`。

## 1. 为什么放客户端

三个创作平台的评论管理页都要求登录态与真实设备指纹，服务端（美国机房 IP）调用必然被风控。因此与 P24 发布一致：**全部在本机 Electron 窗口内用 CDP 执行**，服务端只登记能力 descriptor，云执行器调用时抛中文提示。

## 2. 实现结构

- 抖音 `https://creator.douyin.com/creator-micro/interaction/comment`
- 小红书 `https://creator.xiaohongshu.com/new/interaction`

## 3. 读评论流程（comments）

1. `ensureWindow(platform, true)` 复用窗口池（P29）→ `navigate(commentsUrl)`，失败回落平台首页；
2. `sleep(4000)` 等首屏 → `PROBE_SCRIPT` 判登录态：未登录直接返回 `ok:false` + 「还没有登录 X：请先在「发布」页点「扫码登录」」并落 `comments-login` 截图；
3. `scanCommentsScript` 在页面里跑：候选选择器逐个探测 → 只留可见节点 → 文本 2–600 字 → **按文本去重** → 截断到 `maxItems`（≤50）；
4. 落 `comments` 截图，返回 `{ platform, name, ok, loggedIn, pageTitle, href, selector, items, screenshots, message }`。

`items` 的 `index` 从 0 连续编号，**这是后续回复的唯一定位锚点**（页面刷新后编号可能变化）。

## 4. 回复流程（replyComment）

步骤（每步一张 `reply-*` 截图，失败信息带步骤名）：

1. 打开评论管理
2. 检查登录状态
3. 定位评论并点回复 —— `index` 精确指定第几条，或 `match` 用文本包含匹配；越界/无匹配返回中文错误
4. 填写回复 —— 复用发布用的 `fillField`（CDP `Input.insertText` 填中文，逐候选选择器试）
5. 点击发送 —— 未找到发送按钮返回「没找到发送按钮（选择器可能已变）」
6. 确认回复结果 —— `replyOutcomeScript`：页面出现「回复成功/评论成功/已回复/发送成功」或回复输入框被清空

参数校验（全部中文提示）：`text` 不能为空、≤500 字、必须给 `index` 或 `match`、平台 id 必须在白名单内。

## 5. 已知限制与风险

- **所有选择器零真机验证**（与 P24 相同）：三个平台都是自有前端 + 反自动化，选择器每条至少 3 个候选，但结构一变就全废。失败时读 `%APPDATA%\中科元晟 AI员工\platform-logs\<platform>-<ts>-reply-*.png` 校准。
- 定位靠「第几条」，页面有新评论插入时可能错位 → 优先用 `match`（文本包含）语义。
- 一次只回复一条（避免误发）；批量回复需要循环调用，且不同评论之间要限速。
- 服务端**不登记**该能力的 worker 权限：`platform_*_comment` 不进 `packages/worker/tool-loop.mjs` 的 CAPABILITIES，动平台账号的动作仍由用户在客户端手动触发。

## 8. 真机校准结果（2026-11-09 23:4x–24:0x，0.1.17 + asar 热补丁）

用户 m16075：「三个平台已登录;评论要做」⇒ 本节是评论功能的真机落地记录，也修正了 §5「所有选择器零真机验证」。

### 8.1 视频号：读评论 + 回复已端到端跑通

- 只有**视频号**有网页版评论管理：侧边栏第 3 个图标（无文字）展开「互动管理 → 评论 / 弹幕 / 私信」，地址就是驱动里配的 `https://channels.weixin.qq.com/platform/interaction/comment`。
- 整页在 **wujie 微前端的 shadowRoot** 里：`document.querySelector('wujie-app').shadowRoot`，因此 `document.body.innerText` 永远只有「视频号 · 助手」。驱动新增 `commentShadowHost: 'wujie-app'`，脚本统一走 `__roots()/__all()/__text()`（document + shadowRoot 都查）。
- 页面是「左作品 + 右评论」：左侧 `.comment-feed-wrap`（共 13 个），**必须先点一条作品**右侧才加载评论。驱动新增 `commentFeedItem`，`scanCommentsAcrossFeeds()` 逐作品点开再扫（最多 `COMMENT_FEED_MAX = 8` 个作品），index 跨作品连续编号。
- 结构字段化（避免把动作条/隐藏弹层的「点赞 回复 删除 删除评论？」带进文本）：新增 `commentFields = { author: ['.comment-user-name'], content: ['.comment-content'], time: ['.comment-time'] }`，条目文本组装为 `作者：内容（时间）`。真机输出：
  ```json
  {"ok":true,"loggedIn":true,"selector":".comment-item","items":[{"index":0,"text":"向日葵先生141319：爱跑王子（2024/09/23 01:39）"},{"index":1,"text":"实在是太困：跑姿好帅（2024/05/15 09:31）"}]}
  ```
- 回复真机结果（`replyComment({platform:'shipinhao', match:'爱跑王子', text:'感谢支持，自动化测试回复（可忽略）'})`）：6 步全绿 —— 打开评论管理 / 检查登录状态（已登录）/ 定位评论并点回复（`text=回复`）/ 填写回复（`textarea.create-input`）/ 点击发送（`.create-ft .tag-wrap.primary`）/ 确认回复结果（命中「已回复」）。重复调用多次稳定。

### 8.2 真机踩到的 4 个坑（已修）

1. **ShadowRoot 不能 clone**：`el.shadowRoot.cloneNode(true)` 抛 `NotSupportedError: ShadowRoot nodes are not clonable`，导致深文本恒空 → 视频号永远判未登录。改为逐元素取叶子文本（`DEEP_TEXT_FN` 的 `__deepText()`）。
2. **visible 窗口的 beforeunload 拦截**：`openDebug` 会把窗口导航到 `/platform/post/create`（有未提交表单），此后**窗口可见时任何导航都被拦成 `ERR_ABORTED`**且 URL 不变、旧页面仍 ready ⇒ `navigate()` 会误判成功。修法：评论相关流程一律「先 hide → navigate → 再 showInactive」，并且 `navigate()` 在出现 ERR_ABORTED 时用 `samePath(last.href, url)` 校验是否真的到了目标页（没到就继续等/重试）。
3. **隐藏窗口里 wujie 子应用不挂载**：连续两次调用（comments → replyComment）时第二次导航过去页面只有「视频号 · 助手」，登录检查误判未登录。修法：`打开评论管理` 步骤在 `showInactive()` 之后若深文本仍 <60 字，再导航一次。
4. **textarea 的内容只在 `value` 里**：`fillField` 的 `verifyScript` 原来只看 `document.activeElement` 与深文本，shadow 里的 textarea 两样都读不到 → 报「未接收输入」（截图里文字其实已填好）。修法：`verifyScript` 逐个 root（document + 所有 shadowRoot）查 `input/textarea/[contenteditable]` 的 `value`。
5. **`点击发送` 用了未 attach 的 `evalPage`** → `No target available`。改为 `attachAndEval`。

### 8.3 抖音：网页版确实没有评论管理，且当前登录态已失效

- 侧边栏只有 作品发布 / 首页 / 内容管理 / 数据中心 / 收入变现 / 创作服务；`/creator-micro/interaction/comment`、`/interaction/comment-manage`、`/comment/manage`、`/message/comment` 全部 302 或落「通知」页；`/creator-micro/data-center/interaction` 是互动**数据**页。
- 抖音登录态在本轮失效（openDebug 截图是扫码登录页），**需要用户重新扫码**；`judgeLogin` 已改为以 Electron 分区 cookie（含 httpOnly 的 sessionid）作权威判定，避免登录墙营销长文误命中文案线索。

### 8.4 小红书：网页版无评论管理入口（多轮实测）

- 侧边栏只有 发布笔记 / 首页 / 笔记管理 / Builder hub（小工具、Red Skill）/ 数据看板（账号概览、内容分析、粉丝数据）/ 活动中心 / 笔记灵感 / 创作学院 / 创作百科。
- `/new/interaction`、`/new/comment`、`/comment`、`/new/comment-manage`、`/new/notification` 全部 404（标题「你访问的页面不见了」）。
- 笔记管理页的笔记卡片上只有评论**计数**，点开没有评论列表/回复入口。
- 因此 `DRIVERS.xiaohongshu.commentsSupported = false`，调用时返回中文说明「小红书 创作后台网页版没有「评论管理」入口（2026-11-09 真机核实），暂不支持在这里回复评论」。要覆盖小红书评论，只能走手机端/开放平台（需资质），不在本机 RPA 范围。
