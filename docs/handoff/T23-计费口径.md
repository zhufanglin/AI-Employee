# T-23 模型计费口径（已实现并测试）

> 依据用户 2026-11-04 / 11-05 的决定落地；实现文件 `packages/server/src/compute/compute.service.ts`，隔离测试 `packages/server/src/compute/compute-billing.test.cjs`（5 项全绿）。

## 一、免费额度与积分
- 当月剩余免费额度 > 0：只消耗一次调用额度（`UserMonthlyUsage` +1），不扣积分。
- 额度用尽：走积分。流式请求先按「0 token 价」预扣，流结束后按实际用量多退少补。
- 预扣/补扣/退回全部走 `CreditTransaction`（原版是裸 `user.update`，无流水，无法对账）。

## 二、异常与结算（用户已确认）
1. **正常完成且有 usage**：按实际 token 计价。
2. **中断但上游已返回 usage**：按实际产生的用量计费。
3. **上游未返回 usage（含中断）**：本次不计费；预扣全额退回；`AiUsageRecord.needsReview=true` + `reviewNote` 说明原因，供人工核对后补扣。
4. **余额不足**：余额封顶 —— 只扣到 0，超额部分不向客户追扣；`AiUsageRecord.isPartialDeduct=true`，`creditsCharged` 记录**实扣金额**（不是应扣金额），`reviewNote` 注明「已按余额封顶扣费，差额未追扣」。

## 三、账实一致约束
- 一次请求最多产生一份 `AiUsageRecord`；`creditsCharged` 必须等于该请求实际扣减的积分合计。
- 预扣与结算阶段都不得对同一次请求重复扣款（已修复原版缺陷：预扣后 processBilling 再扣一次）。
- 免费额度路径下 `creditsCharged=0` 且余额不变。

## 四、回归测试覆盖
| 用例 | 断言 |
|---|---|
| 付费额度完成一次流 | 余额只减一次，记录 creditsCharged=1 |
| 中断且无 usage | 预扣全额退回，needsReview=true，creditsCharged=0 |
| 中断但有 usage | 按实际用量计费 |
| 免费额度内 | 余额不变，只消耗额度 |
| 实际费用超过余额 | 余额封顶到 0，记录实扣 3，isPartialDeduct=true |
