# P15 渠道长结果：全文网页 + 摘要 + 链接（T-11 后续）

> 起因：客户在微信里只能看到前 1500 字，一份 7000 字的方案被硬截断。用户 m10573 决定「改成全文存入 OSS 并在前面加摘要和链接」；实施时改为**服务端渲染网页**（理由见下）。

## 1. 为什么不用 OSS 放全文

| 方案 | 问题 |
| --- | --- |
| 直接把 .md 传 OSS 发链接 | 微信内置浏览器遇到 .md/.txt 常直接下载，客户看到的是文件而不是文章 |
| 传 .html 到 OSS 发链接 | 需要给对象设 Content-Type/Content-Disposition，阿里云默认可能强制下载；且对象多了难清理 |
| 私有桶签名 URL | 链接会过期，客户隔天点开 403 |
| **服务端渲染一页 HTML（采用）** | 链接固定 `/api/channels/result/:taskId?t=<签名>`，样式可控、不过期、不需要额外存储，随时能改版 |

## 2. 组成

| 文件 | 作用 |
| --- | --- |
| `packages/server/src/channels/result-page.ts` | `resultToken()` HMAC 签名、`resultUrl()`、`renderMarkdown()`（自带极简渲染器，不引第三方包）、`renderResultPage()` |
| `packages/server/src/channels/result-page.controller.ts` | `GET /api/channels/result/:taskId?t=` 免鉴权结果页；签名错 403、任务不存在/无产出 404 |
| `packages/server/src/channels/dispatcher.service.ts` | `push()` 增加 `longResultText()`：超长时推「前 N 字 + 字数提示 + 链接」 |
| `packages/server/src/channels/channels.module.ts` | 注册 `ChannelResultController` |

## 3. 行为

- 每条渠道有单条上限：企微 600 字、公众号 1800 字、个人微信 1500 字。
- 内容 ≤ 上限：原样发送（行为不变）。
- 内容 > 上限且配置了 `PUBLIC_BASE_URL`：
  ```
  <正文前 (上限-260) 字>……

  （全文约 7469 字，微信里只展示前 1240 字）
  点这里看完整版：
  https://api.fcmediaagent.com/api/channels/result/<taskId>?t=<32位签名>
  ```
- 内容 > 上限但**没有** `PUBLIC_BASE_URL`：退回原来的「……（内容过长已截断）」提示（不会发出半截链接）。
- 失败/超时/需要补充信息等短消息路径不受影响。

## 4. 安全边界

- 结果页**免登录**（微信客户没有平台账号），访问控制靠 URL 里的 `t`：`HMAC-SHA256(CHANNEL_RESULT_SECRET, taskId)` 取前 32 位十六进制。
- 任务 id 本身是 cuid（不可枚举），再加上签名，扫描难度足够。
- 页面只读、只展示该任务的标题/状态/产出文本，不暴露用户手机号等任何账号信息。
- 需要整体作废已发出的链接：改 `CHANNEL_RESULT_SECRET` 并重启 api 即可。
- Markdown 渲染全部走 `escapeHtml()`，链接只放行 `http(s)`，`<script>` 会被转义（单测覆盖）。

## 5. 新增/变更 env

```
PUBLIC_BASE_URL=https://api.fcmediaagent.com   # 长结果链接的根地址；为空则退回截断
CHANNEL_RESULT_SECRET=<32位随机>              # 结果链接签名密钥；为空回落 JWT_SECRET
```

生产已设置：`PUBLIC_BASE_URL=https://api.fcmediaagent.com`、`CHANNEL_RESULT_SECRET`（32 位，写入 `/opt/fcmediaagent/app/.env`，chmod 600）。

## 7. 客户端体验

客户在微信里看到：`已收到，正在处理…` → 前 1200 字正文 → 一行「（全文约 N 字…）」→ 一条可点击链接 → 点开是排版好的整篇（标题层级/列表/引用/链接都能点）。
