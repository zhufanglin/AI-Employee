# P44 生产回归定时化（每天 04:10）

> P44 第三波产出。目标：把「只在手工巡检时才跑」的接口回归变成每天自动跑一次，结果既落盘给人工看，也接进现有监控告警（monitor 第 7 项）。

## 一、目的

- 每天在生产机对本机 api（`http://127.0.0.1:3000`）做一次**只读 / 低成本**回归，尽早发现「健康检查还是绿的、但关键接口已经 500 / 鉴权坏了 / 路由被改没了」这类问题。
- 结果结构化写入 `/opt/fcmediaagent/logs/regression.json`，`monitor.mjs` 每 5 分钟读取：36 小时没更新 → 告警「回归检查 36 小时未跑」；结果为失败 → 告警「回归检查失败：<第一条失败项>」。
- 不改业务数据、不碰生产配置、不需要人工值守。

## 二、跑什么 / 不跑什么

脚本：`scripts/ops/prod-regression.mjs`（Node 24 纯内置，零第三方依赖）。固定 6 项，顺序如下：

| # | check | 请求 | 判定 |
| --- | --- | --- | --- |
| 1 | `health` | `GET /api/health` | HTTP 200 且响应体 `db === "up"` |
| 2 | `sms_login` | `POST /api/auth/sms/send` + `POST /api/auth/sms/login` | 只对 `DEV_SMS_ALLOWLIST` 命中的测试号走 devCode 登录，拿到 `accessToken` |
| 3 | `employees` | `GET /api/employees/mine`（带 JWT） | 返回 `items` 数组且 `total` 为数字 |
| 4 | `capabilities` | `GET /api/capabilities`（带 JWT） | `total >= 1` 且 `items.length === total` |
| 5 | `memory_stats` | `GET /api/memory/stats`（带 JWT） | `total` 为数字、`byKind` 为对象 |
| 6 | `credits` | `GET /api/credits/balance`（带 JWT） | `balance` 为数字 |

说明：

- 真实契约里没有 `/api/auth/sms/verify`、`/api/credits/summary`，脚本用的是上面实际存在的路由（`/api/auth/sms/login`、`/api/credits/balance`）。
- 登录只走 **devCode 分支**：手机号必须命中生产 `/opt/fcmediaagent/app/.env` 里的 `DEV_SMS_ALLOWLIST`（默认测试号 `13900000002`）。服务端没返回 `devCode` 时直接判失败并停止，**绝不猜验证码、绝不触发真实短信**。
- 短信接口有 60 秒重发限制：每天定时跑一次不受影响；手工连续重跑可能收到「验证码发送过于频繁」，等 60 秒再跑即可。

**明确不做**（这些是本地 `scripts/prod-verify-*.mjs` 的职责，会消耗积分 / 产生真实数据，不适合天天自动跑）：

- 不创建员工、不安装员工、不创建员工任务；
- 不发媒体任务、不调用上游模型；
- 不写任何业务数据、不改配置、不重启服务；
- 唯一写入是结果文件 `regression.json` 和摘要日志 `regression.log`。

## 三、部署步骤（生产机 47.85.46.165）

在仓库根目录（本机）执行：

```bash
# 1) 传文件到 /tmp
scp scripts/ops/prod-regression.mjs            root@47.85.46.165:/tmp/
scp ops/systemd/fcmediaagent-regression.service root@47.85.46.165:/tmp/
scp ops/systemd/fcmediaagent-regression.timer   root@47.85.46.165:/tmp/
```

登录生产后安装：

```bash
# 2) 主程序落位（root 可读写 /opt/fcmediaagent/logs）
sudo install -m 0755 -o root -g root /tmp/prod-regression.mjs /opt/fcmediaagent/ops/prod-regression.mjs

# 3) systemd 单元
sudo install -m 0644 /tmp/fcmediaagent-regression.service /etc/systemd/system/fcmediaagent-regression.service
sudo install -m 0644 /tmp/fcmediaagent-regression.timer   /etc/systemd/system/fcmediaagent-regression.timer
sudo systemctl daemon-reload

# 4) 先手工跑一次（不依赖 timer），确认 6 项输出与退出码
sudo /opt/node/bin/node /opt/fcmediaagent/ops/prod-regression.mjs --once; echo "exit=$?"
cat /opt/fcmediaagent/logs/regression.json
tail -n 3 /opt/fcmediaagent/logs/regression.log

# 5) 启用定时器（每天 04:10，Persistent=true）
sudo systemctl enable --now fcmediaagent-regression.timer
systemctl list-timers fcmediaagent-regression.timer --no-pager
```

说明：

- `ExecStart=/opt/node/bin/node /opt/fcmediaagent/ops/prod-regression.mjs --quiet`：`--quiet` 下成功不打印，失败只把失败项与摘要写到 stderr，避免日志噪音。
- `WorkingDirectory=/opt/fcmediaagent`；`StandardOutput/StandardError=append:/opt/fcmediaagent/logs/regression.log`，与脚本自己追加的摘要行同文件。
- `Persistent=true`：关机 / 宕机错过 04:10 时，开机后补跑一次；`RandomizedDelaySec=120` 错峰 2 分钟。
- 脚本自己从 `/opt/fcmediaagent/app/.env` 读 `DEV_SMS_ALLOWLIST`，无需额外环境文件；也可用环境变量 `REGRESSION_BASE_URL` / `REGRESSION_PHONE` / `REGRESSION_OUT` / `REGRESSION_ENV_FILE` 覆盖。

## 五、失败怎么排

| 现象 | 排查 |
| --- | --- |
| `health` 失败 | `systemctl status fcmediaagent-api`；`curl -s http://127.0.0.1:3000/api/health`；`db=down` 时看 MySQL 容器与 `DATABASE_URL` |
| `sms_login` 报「不在 allowlist」 | 确认 `/opt/fcmediaagent/app/.env` 的 `DEV_SMS_ALLOWLIST` 含 `13900000002`（或 `--phone` 指定名单内号码）；注意生产环境不会返回真实验证码 |
| `sms_login` 报「未返回 devCode」 | 号码没命中服务端名单，或 `.env` 改了但 api 没重启；不要反复重跑（60 秒频率限制） |
| `sms_login` 报 HTTP 400「发送过于频繁」 | 刚手工跑过，等 60 秒；每天定时跑不会触发 |
| `employees` / `capabilities` 等 401/403 | 登录 token 没拿到，先修 `sms_login`；也可能是 JWT 密钥/权限变更 |
| 某接口 404 | 路由被改或未部署新版本：对照 `docs/fidelity-matrix.md` 与 `packages/server/src/**/*.controller.ts`，用 `curl` 手工确认 |
| 结果一直 `ok=false` 但手工 `curl` 正常 | 看 `checks[].detail.message` 的期望结构；若响应体字段确实变了，需同步更新脚本的 `validate` |
| monitor 报「36 小时未跑」 | `systemctl list-timers fcmediaagent-regression.timer`；`systemctl status fcmediaagent-regression.service`；看 `regression.log` 是否有写权限错误 |
| timer 到点没跑 | `systemctl list-timers --all`；确认系统时区是 Asia/Shanghai；`journalctl -u fcmediaagent-regression.service` |

手工单跑（只读，安全）：

```bash
sudo /opt/node/bin/node /opt/fcmediaagent/ops/prod-regression.mjs --once --json   # stdout 完整 JSON
sudo /opt/node/bin/node /opt/fcmediaagent/ops/prod-regression.mjs --dry-run       # 只打印计划，不联网不写文件
```

退出码：`0` 全部通过；`1` 存在失败项或写结果失败；`2` 参数错误。

## 六、与 monitor 的关系

- 本脚本只负责「跑 + 落盘」，不推送、不发告警。
- `scripts/ops/monitor.mjs` 新增第 7 项 `prod_regression`（每 5 分钟一轮）：
  - `regression.json` 不存在：生产机记 `skip`（未部署，不算告警），开发机记 `skip`（本机无生产环境）；
  - `at` 超过 `appRegression.maxAgeMinutes`（默认 2160 分钟 = 36 小时）：`fail`「回归检查 36 小时未跑」；
  - `ok !== true` 或存在 `checks[].ok === false`：`fail`「回归检查失败：<第一条失败项的 detail.message>」；
  - 否则 `ok`「回归检查通过：N 项全绿（X 小时前）」。
- 配置项（`monitor.config.json`，全部可省略）：

  | 配置项 | 默认值 | 说明 |
  | --- | --- | --- |
  | `appRegression.enabled` | `true` | 是否启用第 7 项 |
  | `appRegression.jsonPath` | `/opt/fcmediaagent/logs/regression.json` | 回归结果文件 |
  | `appRegression.maxAgeMinutes` | `2160` | 结果最大年龄（36 小时） |

- 告警链路复用 monitor 现有 webhook（企业微信/钉钉）、60 分钟冷却与「已恢复」通知，无需单独配置。

## 七、回滚

```bash
sudo systemctl disable --now fcmediaagent-regression.timer
sudo rm -f /etc/systemd/system/fcmediaagent-regression.timer /etc/systemd/system/fcmediaagent-regression.service
sudo systemctl daemon-reload
# 可选：保留 /opt/fcmediaagent/ops/prod-regression.mjs 与 logs/regression.* 以备查
```

回滚后 monitor 第 7 项会因结果文件超过 36 小时而告警；若不希望告警，把 `appRegression.enabled` 设为 `false`。
