export const DEFAULT_READ_BYTES = 200000

返回结构：成功统一带 `ok: true`（错误经 `{ ok: false, error }`，错误文案为中文）；`files:open` 成功时 `{ ok: true }`，`shell.openPath` 返回非空错误串时带 `error` 但仍是 `ok: true`（契约要求）。

## 3. IPC 通道

全部在 `registerFileOps` 里注册，入参都是单个对象；`path`/`dir` 可以是绝对路径（渲染层直接用 `files:list` 返回的 `path`），也可以是相对工作区根的路径。

| 通道 | 入参 | 成功返回 | 关键行为 |
| --- | --- | --- | --- |
| `files:list` | `{ dir?: string }` | `{ ok: true, dir, items: FileItem[] }` | 缺省 `dir` = 工作区根；目录优先、同类型按名称升序（`localeCompare('zh-CN', { numeric: true })`）；自动创建根目录 |
| `files:read` | `{ path: string, maxBytes?: number }` | `{ ok: true, path, text, truncated }` | 默认 200000 字节；`maxBytes` 夹在 [1, 2MB]；内容含 `\u0000` → `{ ok: false, error: ERR_BINARY }`；只读前 N 字节，多字节 UTF-8 尾部不会读到半个字符 |
| `files:write` | `{ path: string, text: string }` | `{ ok: true, path, size }` | 父目录不存在自动 `mkdirSync(recursive)`；目标是文件夹 → 报「目标是文件夹，不能写入文本」 |
| `files:mkdir` | `{ path: string }` | `{ ok: true, path }` | 多级自动创建；已存在不报错 |
| `files:rename` | `{ path: string, name: string }` | `{ ok: true, path }` | `name` 不能含路径分隔符（`/` 或反斜杠）、不能是 `.`/`..`、不能为空，否则「名称不能包含路径分隔符」；只改名，不跨目录移动 |
| `files:delete` | `{ path: string }` | `{ ok: true }` | 文件 `unlinkSync`、目录 `rmSync(recursive)`；拒绝删除工作区根目录本身（「不能删除工作区根目录本身」） |
| `files:reveal` | `{ path: string }` | `{ ok: true }` | `shell.showItemInFolder`；路径不存在时给出中文错误 |
| `files:open` | `{ path: string }` | `{ ok: true, error? }` | `shell.openPath`；空串视为成功 |

### 安全校验（逐字契约）

1. 所有入参先 `path.resolve`（相对路径以工作区根为基准），再做字面包含判断：`relative(root, target)` 不得以 `..` 开头、不得是绝对路径；Windows 比较忽略大小写。工作区根本身允许（`files:delete` 另行拒绝）。
2. 再对「最近的存在祖先」`realpathSync`，若真实路径不在真实根目录内（目录联接 / 符号链接指向外部、或链接悬空），同样拒绝。`root\link\..\..` 这类拼接会先被字面校验拦下，`root\link\evil.txt` 会被真实路径校验拦下。
3. 越界一律抛 `ERR_OUTSIDE`（「路径超出工作区范围」），`registerFileOps` 统一转成 `{ ok: false, error }`，渲染层直接展示。

## 4. 渲染层页面

`Workspace.tsx`（默认导出 `Workspace`）：

- 顶部：面包屑（「工作区」起，可点击任意一级）+「新建文件夹」「新建文件」输入框与按钮。
- 左栏：`.card` 内 `.table`，列为名称/大小/修改时间；目录行显示 `[目录]` pill；单击选中并预览，双击目录进入、双击文件交给系统打开。
- 右栏：只读预览（等宽字体），显示大小/修改时间/绝对路径；超过 200000 字节时提示「已截断，仅显示前 200000 字节」；二进制错误时展示契约文案和「交给系统程序打开」按钮。
- 选中项操作：「打开」「在文件夹中显示」「删除」；删除先弹二次确认（notice.err，说明不可恢复、目录会连同内容一起删除）。
- 数据全部经 `window.fcm.files`；`window.fcm.files` 不存在时页面给出「文件管理接口尚未接线…」中文提示，不会白屏（Lead 接线前也可安全挂载）。
- 样式只用页面内联 `<style>` 的 `workspace-*` 类 + 既有 `.page/.card/.table/.ghost/.primary/.pill/.notice/.muted/.empty-state` 等，未改 `styles.css`。

## 5. 冒烟测试

```powershell
node scripts/smoke-p27-file-ops.mjs
```

脚本不依赖真实 Electron：用仓库根 `node_modules` 里的 esbuild（0.28.2）把 `file-ops.ts` 打成 CJS 到系统临时目录，`electron` 别名指向内存桩（`shell.openPath` 返回空串），再用假的 `ipcMain.handle` 收 8 个通道逐条断言。临时目录（含工作区与 junction 外部目录）测试结束即删。

覆盖：8 个通道注册；list/read/write/mkdir/rename/delete 正常路径；默认 `dir`、目录优先排序、size/mtime/isDir；自动建父目录；二进制判定与逐字文案；`maxBytes=4`、默认 200000、上限夹到 2MB 三种截断；`..\..` 与 `C:\Windows` 越界（读写/list，断言文案「路径超出工作区范围」且未落盘）；工作区根删除拒绝；rename 带分隔符拒绝；错误文案（读文件夹、list 不存在、list 文件、write 覆盖文件夹）；`files:reveal`/`files:open`；Windows 目录联接（junction）逃逸读写拒绝。
