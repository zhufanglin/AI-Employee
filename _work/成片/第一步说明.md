# 第一步：克隆人 + 声音克隆（交付说明）

时间：2026-11-11 00:45　执行：dsh-lead

## 一句话

给软件一张照片 + 一段音频样本 + 一段文稿，它会用**已有的两个模型**产出：
1. 用样本音色朗读文稿的**克隆音色音频**（indextts）；
2. 让照片里的人物按这段音频说话的**克隆人口型视频**（lipsync / musetalk）。

## 调用的软件接口（全部走复刻服务端，没有直连上游）

```
POST /api/media/files/upload          照片、音频样本 → openapi/xxx.png / .m4a
POST /api/clone-records               {type:"voice", sourceUrl:样本, text:文稿} → indextts
   GET /api/clone-records             轮询，status=completed 后 resultUrl 指向 /uploads/media/<taskId>.mp3
POST /api/media/files/upload          克隆出来的 mp3 再上传一次（lipsync 只能读 RunningHub 内的素材）
POST /api/compose-videos              {composeType:"lipsync", videoUrl:照片, sourceAudioUrl:音频, seconds:27, resolution:"1080", fps:25}
   GET /api/compose-videos            轮询，status=completed 后 resultUrl 指向 /uploads/media/<taskId>.mp4
```

## 本次发现的产品问题（重要）

1. **音色克隆在复刻代码里被硬禁**：`packages/server/src/media/media.service.ts:292`（改前）直接抛
   `BadRequestException("音色合成时长暂无法确认，体验版暂不支持提交")`，导致桌面端「音色克隆」
   页必然 400。已按 `MediaPricing` 的 `per_request` 计费放通（删掉该行），并用 3100 实例验证成功。
2. **「克隆人」没有实体**：软件里只有一次性的 lipsync（照片每次都重传），没有“人物记录”可复用，
   也没有“声音模型”可复用（每次合成都要带样本音频）。第二步要复用，「克隆人 / 音色」需要落库成实体。
3. **端口 3000 上的旧服务进程我无权限重启**（PID 20088，Access denied）。要让桌面端立刻用上第 1 条的修复，
   需要手动 `scripts\dev-down.ps1` + `scripts\dev-up.ps1` 重启本地服务端；本次验证跑在 3100。
