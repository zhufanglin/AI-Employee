# P45-3 AI 声明 + P45-4 举报与投诉

## P45-3 桌面 RPA 发布自动勾选「AI 生成」声明

### 为什么

三平台（抖音/小红书/视频号）发布页都有"内容由 AI 生成"类声明选项，平台规则要求 AIGC 内容必须声明。员工自动发布时如果漏勾，作品可能被限流或下架。

### 实现

`packages/desktop/src/main/platform-drivers.ts`

```ts
export interface PlatformDriver {
  // ...
  aiDeclarationTexts: string[];   // 必填，用于在页面上找"AI 生成"勾选项
}
```

| 平台 | aiDeclarationTexts |
| --- | --- |
| douyin | 内容由AI生成 / 由AI生成 / 内容为AI生成 / AI生成 |
| xiaohongshu | 笔记含AI生成内容 / 含AI生成内容 / AI生成 |
| shipinhao | 内容由AI生成 / 由AI生成 / AI生成 |

`packages/desktop/src/main/platform.ts`

- `aiDeclareScript(texts)`：在页面里查 `label` / `[role=checkbox]` / `input[type=checkbox]` / `.semi-checkbox` / `.checkbox` / `div` / `span` / `button` / `li`，文本 ≤40 字且包含关键词，按文本长度升序取最短命中；已勾选直接返回 `already-checked`，否则 `(el.closest('label')||el).click()`。
- `markAiDeclaration(win, driver)`：`attachAndEval` 执行；catch 住异常，返回「未找到 AI 生成声明入口…已在正文里保留 AI 说明」**不抛**（声明失败不应阻断发布）。
- doPublish 在「填写正文」之后插入：

```ts
await run('AI 生成声明', async () => this.markAiDeclaration(w, driver), false); // false = 非 critical
```

### 验证

web `tsc` = 0；`electron-vite build` = 0。真机验证时 run.log 里能看到「AI 生成声明」这一步的结果文案。

## P45-4 举报与投诉（服务端 + 桌面端 + 运维后台）

### 为什么

《生成式人工智能服务管理暂行办法》要求提供"便捷的投诉、举报入口"，并在收到投诉后及时处理反馈。

### 数据模型

`packages/server/prisma/schema.prisma` 末尾：

```prisma
model ReportTicket {
  id          String   @id @default(cuid())
  userId      String?
  category    String   @db.VarChar(32)
  content     String   @db.Text
  contact     String?  @db.VarChar(120)
  targetUrl   String?  @db.VarChar(500)
  source      String   @default("api") @db.VarChar(32)
  ip          String?  @db.VarChar(64)
  userAgent   String?  @db.VarChar(255)
  status      String   @default("open") @db.VarChar(16)
  handledBy   String?  @db.VarChar(64)
  handledNote String?  @db.VarChar(500)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  @@index([status, createdAt])
  @@index([userId, createdAt])
  @@map("ReportTicket")
}
```

**刻意不建 User 外键**：未登录用户也要能匿名举报。
迁移：`packages/server/prisma/migrations/20261112141829_p45_report_ticket/`。

### 服务端

`packages/server/src/legal/report.service.ts`

- `CATEGORIES`：`ai-content | illegal | copyright | privacy | billing | bug | other`（7 类，`CATEGORY_LABELS` 提供中文）。
- `submit(input, actor)`：类别白名单校验（400「请选择举报类别（…）」）；正文 5–2000 字；contact/targetUrl/source/userAgent 自动截断；IP 限流 `RATE_LIMIT_MAX=10` 次 / `RATE_LIMIT_WINDOW_MS=3600000`（超限 429「举报提交过于频繁，请稍后再试」）；成功 `logger.warn` 打一行便于巡检。
- `categories()` / `list({status,category,limit})` / `resolve(id,{status,handledBy,handledNote})`。

路由：

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/legal/report/categories` | 公开 | 类别清单（渲染端下拉用） |
| POST | `/api/legal/report` | 公开（带 token 则记 userId） | 提交举报 |
| GET | `/api/admin/reports?status=&category=&limit=` | admin | 工单列表（含 openCount） |
| POST | `/api/admin/reports/:id/resolve` | admin | 标记 resolved/rejected + 处理说明 |

**注意**：`/legal/report*` 必须声明在 `@Get(":key")` 之前，否则会被当成条款 key。POST 管理端接口要 `@HttpCode(HttpStatus.OK)`（Nest 默认 201 会让验收脚本假失败）。

### 桌面端

- `packages/desktop/src/main/index.ts`：IPC `legal:report` → `POST /api/legal/report`，返回 `{ ok, id?, message?, error? }`。
- `packages/desktop/src/preload/index.ts`：`legal.report(p)`。
- `packages/desktop/src/renderer/src/types.ts`：`LegalReportResult`。
- `packages/desktop/src/renderer/src/pages/Settings.tsx`：「关于与合规」下面新增「举报与投诉」卡片 —— 7 类下拉、正文 textarea（≤2000）、可选联系方式、提交后显示工单号。

### 运维后台

`packages/server/public/admin/app.js`：导航新增「举报工单」（在"充值与定价"与"站点配置"之间），支持 open/resolved/rejected/all 过滤、一键标记已处理/驳回并填写处理说明。

**部署注意**：后台 SPA 由 `main.ts` 的 `serveStatic(join(__dirname,'..','public','admin'))` 提供，生产路径 `/opt/fcmediaagent/app/public/admin/`。**只换 dist 不拷 public/admin 会导致举报工单页 404。**
