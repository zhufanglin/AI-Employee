## 一、后台短信配置接 DB（原问题：后台配了不生效）

原实现 `packages/server/src/auth/sms.sender.ts` 只读 env（`ALIYUN_SMS_ACCESS_KEY_ID` 等），管理后台 `SmsConfig` 表是死配置。现改为：

- 新增 `SmsResolvedConfig` 与解析链：**DB（isActive=true）> env > 开发模式逐字段回落**；模块级缓存 60s，`export invalidateSmsConfigCache()`；读库异常只 warn 再回落 env，不让登录被配置表拖挂。
- `aliyunSend()` 全部改用解析后的配置；`provider !== "aliyun"` 直接抛「暂不支持的短信服务商：xxx」。
- `send()` 返回 `{ sent, devCode, provider, message }`；`DEV_SMS_ALLOWLIST` / `returnCodeAllowed`（P43 P0 的 devCode 泄露修复）原样保留。
- `packages/server/src/admin/admin-extra.service.ts` 注入 `SmsSender`，`updateSmsConfig` 保存后调用 `invalidateSmsConfigCache()`；`testSms()` 从「只校验格式」改为**真实下发**（randomInt 6 位、purpose=admin-test），返回 `{ sent, provider, message }`。
- 依赖装配：`auth.module.ts` exports 增加 `SmsSender`；`admin.module.ts` imports 增加 `AuthModule`。

## 三、asar 增量热更新（替代每次 6–13 分钟的 NSIS 安装）

原版 IPC 有 `asar-update:check/download/install/status` 四条（`contracts/ipc_handles_147.tsv`），复刻缺失，导致每改一行都得整包重装。新增 `packages/desktop/src/main/asar-update.ts`：

- IPC：`asar-update:status | check | download | install`，统一返回 `{ ok, data?, error? }`，中文报错。
- 更新源：`https://updates.fcmediaagent.com/desktop/asar/asar.json`，形如 `{ version, file, sha512, size, minVersion }`。
- **版本判定只用清单里的 version**：检查发生在下载之前，磁盘上的 `app.asar` 仍是旧包，且包内 `package.json` 需解包才能读。清单 version 由 `scripts/publish-asar.mjs` 从 `packages/desktop/package.json` 生成，是单一事实源。
- 下载：边下边算 sha512，>200MB 或 hash/大小不符即删文件并中文报错；URL 强制同 origin 且在 base 路径前缀下，`file` 只允许 basename。
- 安装：hide 窗口 → 当前 `app.asar` rename 成 `app.asar.bak-<ISO时间戳>`（rename 失败退化为 copy+rm）→ 写入新包；失败自动回滚到备份，成功 400ms 后 `app.relaunch() + app.exit(0)`。
- 回滚方法（写进文档给用户）：关闭客户端，把 `resources` 下的 `app.asar.bak-<时间戳>` 复制回 `app.asar` 再启动；每次安装生成新备份，不自动删除。
- 发布：`node scripts/publish-asar.mjs` 默认只打包，`--upload` 才 scp 到 `/opt/fcmediaagent/updates/desktop/asar/`。

## 五、审批：驳回重跑 + 超时自动通过

- `packages/server/src/employee/employee.service.ts`：`const RETRY_LIMIT = 2;`；`reject(userId, id, body)` 支持 `body.rerun === true`——校验 status 必须是 `awaiting_approval`，`attempts >= RETRY_LIMIT` 抛「该任务已重跑 2 次，仍不合格，请调整需求后重新派活」；`$transaction` 内清 `employeeTaskArtifact`、状态回 `queued`、清 startedAt/finishedAt/error/outputText/outputPath，`outputMeta` 保留但去 `claimToken`，累加 attempts/rejected/reviewReason/lastRejectedAt。
- `async autoApproveOverdue(hours)`：`hours <= 0` 直接返回 0；查 `awaiting_approval` 且 `updatedAt < now - hours`（take 200）逐条置 `succeeded` + `outputMeta.autoApproved / approvedAt / reviewReason「超过 N 小时未验收，自动通过」`。
- `employee-expiry.service.ts`：注入 `EmployeeService`，env `EMPLOYEE_APPROVAL_TIMEOUT_HOURS`（默认 0 = 关闭），`status()` 暴露 approvalTimeoutHours，`runOnce` 里 >0 才调用并 try/catch warn，`EmployeeExpiryRun` 增 `autoApproved` 计数。
