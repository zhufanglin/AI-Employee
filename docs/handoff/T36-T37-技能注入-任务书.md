# T-36 / T-37 / T-38 员工技能注入（2026-11-06）

## 为什么做
17 个 AI 员工现在的执行提示词只由 `AiEmployee` 的 name/title/mission/coreDirective/description/capabilities/kpi/usageExample 拼成，**完全不读技能包里的 `SKILL.md`**。结果是：员工知道“自己是谁”，但不知道“按什么流程干活、输出什么格式、有哪些硬规则”——交付质量与技能的固定输出模板脱节。

实测证据：生产任务 `cmw3z0it6001zrzb4npql7v3y`（boss-daily-lead-topics）执行链 steps = `[web_extract ok, finish ok]`，产出可用但**没有按 SKILL.md 的固定输出格式**（缺少技能里要求的字段顺序与自检清单）。

## 数据流（三层）
```
packages/desktop/resources/skills/<slug>/SKILL.md      （源，随包/随仓库）
        │  T-38 生成脚本（离线，一次）+ 校验
        ▼
packages/server/prisma/skills-content.ts               （提交进仓库，生产 seed 只需它）
        │  T-36 seed 写入
        ▼
AiEmployee.skillMd   （DB 列，Text）
        │  T-36 employee.service 在 detail() 与 pullTasks() 里返回
        ▼
员工执行器 system prompt   （T-37：桌面 executor.ts 与云端 worker tool-loop.mjs 共用）
```

## T-38（子 Agent）：技能内容生成器
- 文件：`scripts/gen-skills-content.mjs`（读 `packages/desktop/resources/skills/*/SKILL.md`）+ `scripts/check-skills-content.mjs`（校验）。
- 产物：`packages/server/prisma/skills-content.ts`，形如
```ts
export const SKILL_CONTENT: Record<string, string> = {
  'boss-lead-radar': `---\nname: ...\n---\n...全文...`,
};
export const SKILL_CONTENT_VERSION = '<iso date>';
```
- 要求：17 个 slug 全部收录；保留原文（含 YAML frontmatter）；单条截断上限 12000 字符；生成结果按 slug 排序；脚本可重复执行（幂等）。
- 校验：条数 = 目录数；每条长度 ≥ 500 且 ≤ 12000；每条必须包含 `name:` 与 `description:`；缺任何一条退出码 1。
