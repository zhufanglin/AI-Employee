# P18 长期记忆检索（上线记录）

> 日期：2026-11-07　执行：dsh-lead　生产：47.85.46.165

## 1. 为什么做

到 P17 为止，员工每个任务都是"失忆"的：同一个客户问第二次价格，员工不知道上次报过什么；同一个老板交代过的偏好（要口语化、不要长表格、报价按季度）每次都得重说。

原来的"记忆"只有两处：会话历史（服务端 messages，按会话隔离）和工作区文件（要模型主动 file_read）。跨会话、跨员工的知识没有落点。

所以 P18 增加一张通用记忆表 + 4 个能力，让员工自己决定什么时候记、什么时候查。

## 2. 设计决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 作用域 | 按 `userId` 隔离，同一用户的员工共享 | 老板的助理、销售、内容员工应该共用一份"公司常识"；跨用户绝不能串 |
| 存储 | MySQL `AgentMemory` 表 | 已有 MySQL，无需引入新存储 |
| 检索 | Prisma `contains`（LIKE）取最近 200 条候选 + JS 打分排序 | 单用户记忆量只有几百条；没有 embedding 凭证，向量库成本不划算 |
| 打分 | 正文命中数 + 标题×3 + 标签×2 + 新鲜度衰减 + hitCount 加成 | 短标题命中比长正文命中更可信；常用记忆往上浮 |
| kind | `note`（默认）/ `fact` / `preference` / `lesson` | 覆盖"备注、事实、偏好、踩过的坑"四类，够用且不冗余 |

## 3. 能力

| 能力 | 参数 | 行为 |
| --- | --- | --- |
| `memory_save` | `content`（必填，≤4000 字）、`title`（≤191）、`tags`（≤10 个，合计 ≤512）、`kind` | 落库并返回 id |
| `memory_search` | `query`（必填）、`limit`（默认 10） | 返回 `{total, items:[{id,kind,title,content,tags,score,createdAt}]}`，命中即 hitCount+1 |
| `memory_list` | `limit`、`kind` | 按创建时间倒序，用于"你还记得什么" |
| `memory_delete` | `id` | 只能删自己的，不存在/越权一律"记忆不存在或不属于你" |

模型侧引导（`packages/worker/tool-loop.mjs` INSTRUCTIONS）：客户偏好/报价口径/项目结论/踩过的坑用 `memory_save`；回答老客户问题前先 `memory_search`。

## 6. 坑

1. **tar 包内已带 `p18x/` 前缀时不能再用 `tar -xzf x.tgz -C p18x`**，否则解出 `p18x/p18x/...`，`set -e` 脚本在第 6 行静默退出（日志 0 字节、退出码 1），看起来像"部署成功但其实什么都没换"。正确写法：`cd /opt/fcmediaagent && rm -rf p18x && tar -xzf p18.tgz`。排查手法：`bash -x script.sh > log 2>&1`。
2. `scripts/verify.ps1` 里的 `smoke-capabilities.mjs` 直接 `new PrismaClient()`，跑全量 verify 前必须先 `$env:DATABASE_URL='mysql://fcm:fcm_dev_pass@127.0.0.1:3306/fcmediaagent_v2'`，否则 `Environment variable not found: DATABASE_URL`。
3. 本地 `prisma generate` 稳定报 `EPERM ... query_engine-windows.dll.node.tmpNNN`，JS 侧其实已更新，验 `node_modules/.prisma/client/index.js` 里是否含新 model 名即可，不必纠结退出码。
4. 生产 `app/node_modules/.prisma/client` 是 Linux 引擎，**不能整目录拷本地 `.prisma/client`**，必须在生产机上 `prisma generate`。

## 7. 还没做

- 记忆不会自动清理/合并（同一件事说三次就有三条）。后续可加"相似度去重"或按 `updatedAt` 做 TTL。
- 没有 embedding 语义检索：`memory_search` 是关键词 LIKE，问"价格"查不到"报价"。要上语义检索需要 embedding 凭证 + 向量列。
- 记忆不进系统提示：现在是模型主动 `memory_search`，不是每轮自动注入相关记忆（延迟考虑）。如果发现模型不爱搜，可以在 worker 里做"每轮预检索 top3 注入"。
