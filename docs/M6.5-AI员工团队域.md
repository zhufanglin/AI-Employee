## 2. 与原版语义的差异（决定数据模型）

- 原版：12 员工 = **agent（SOUL 人格 + 41 个定时 workflow）**，按套餐 presets 一键创建，人格文案在服务端接口下发。
- 现在：17 员工 = **skill（SKILL.md 能力包）**。SKILL.md 描述的是"怎么做这件事"，不是"这个人格是谁"。
- 因此定三层：`Employee（角色卡：中文名/图标/一句话介绍/分类）` → `Skill（能力包，默认 1:1）` → `Cron（触发时机）`。
  以后一个员工挂多个 skill（如"销售经理"= 销售跟进 + 聊天成交分析）只需改绑定，不动代码。

## 3. 加载机制（openclaw 实测）

技能搜索优先级（`resources/openclaw/docs/concepts/agent.md:66-68`、`help/faq.md:175`）：
`<workspace>/skills` > `~/.openclaw/skills`（managed）> `skills.load.extraDirs`（最低）。

我们的做法：
- 桌面端已设 `OPENCLAW_HOME=<userData>/openclaw`，安装目标 = `<userData>/openclaw/skills/<skill-name>/`。
- 出包时 17 个 skill 放 `resources/skills/`，点"安装"时复制过去（并可写 `skills.load.extraDirs` 兜底）。
- 升级：`skill-manifest.json` 带 version，比本地新就覆盖 + 记录到 EmployeeInstall.version。
- per-agent 过滤：openclaw 支持 agent skill allowlist，用于"只给安装过的员工开放对应技能"。

## 5. 架构决定：云端调度 + 端上执行

硬事实：老板的电脑不会 24 小时开着，原版靠本机计划任务跑 41 个 workflow，关机就不跑。

- **云端（NestJS @nestjs/schedule）**：维护 EmployeeCron，到点插入 EmployeeTask(status=queued, runAt)。
- **13/17 个 skill 是纯提示词 + 联网分析**，不依赖本机 → **直接在云端执行**，电脑关机也能出日报/选题/跟进名单。
- **4 个需要本机能力**（视频剪辑、公众号发布、本地文件、微信）→ queue 给桌面端：`GET /api/employee-tasks/pull` 长轮询取任务 → 调 openclaw agent 或本地 CLI → `PATCH /api/employee-tasks/:id` 回传。
- **补跑**：桌面端启动时拉 `runAt < now && status=queued`，missedCount++，单次最多补 3 条。
- **离线判定**：任务下发给端上后 5 分钟无心跳 → failed(reason=client_offline)，并在看板标"电脑未开机"。

## 6. 授权与计费

- 三档套餐：体验（3 员工）/ 标准（17 全部）/ 旗舰（+代运营），由 `AiEmployee.tier` + 兑换码/支付开通。
- 计费：任务级扣积分——纯文本 1、含图 20、含视频 20+（沿用 MediaPricing，但**价格必须你重新定**）。
- 到期：`AiEmployeeInstall.expiresAt` 到期 → enabled=false，界面提示续费。

## 10. 验收标准（改以 skill 为准，不以原版功能表为准）

每个 skill 必须能在客户端里**一键跑出可用产物**，共 17 条 checklist；其中：
- 14 视频剪辑：需要打包 ffmpeg/ffprobe（`resources/bin` 已有 node.exe/npm.cmd/uv.exe 的位置可放）；
- 15 公众号发布：需要公众号 AppID/AppSecret + 服务器 IP 白名单；
- 7 外贸 / 1 线索雷达 / 8 小红书 / 5 同行雷达 / 10 GEO：需要联网搜索能力（可走搜索引擎 API 或 openclaw browser 插件）；
- 3 评论区 / 4 聊天记录 / 9 私域：依赖导入模板（已随包提供 6 个）。
