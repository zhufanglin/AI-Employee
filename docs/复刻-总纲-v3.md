## 一、先定义「忠实」：五层忠实度，逐层可验收

只按功能清单打勾，最后会得到「看着像、跑起来不一样」的软件。所以定义五层：

| 层 | 内容 | 验收方式 | 当前状态 |
|---|---|---|---|
| **F4 架构** | 进程模型（Electron 主/渲染 + openclaw 网关 + 本地 CLI）、网关 18789 token 协议、更新通道 | 架构图对照 + 端到端链路跑通 | 已有（W2/W3） |
| **F3 行为** | 状态机（任务 status 流转）、计费规则（额度优先→积分、预扣→结算→退款）、错误码与文案、重试与补跑 | 契约测试（对着原版行为写断言） | 部分（计费已对齐） |
| **F2 契约** | 238 HTTP 路由、147 IPC 通道、47 表结构、事件名、字段名 | 机器 diff（路由/通道/表/字段四张表） | 待建基线 |
| **F1 文案** | 用户可见中文文案、错误提示、按钮、空状态、引导 | 文案抽取对照表 | 未开始 |
| **F0 视觉** | 页面结构、布局、配色、图标 | 页面级截图对照 | 部分（对话页） |

**判定口径**：F2 必须 100% 对齐（否则老配置接不上）；F3 关键链路（登录/计费/任务/渠道）行为等价；F1/F0 允许「视觉近似、文案一致」。

## 五、本次整理出的盲点（按影响排序）

1. **agent 上下文层完全没做**：原版启动把 AGENTS.clawx.md + TOOLS.clawx.md 注入 agent（含「先试工具再拒绝」规则）。缺这层，行为会明显不同，是 F3 忠实的核心。
2. **预装 11 个技能是原版「能干活」的底盘**：agent-tool-box（统一调飞书/抖音/VX机器人/公众号/MySQL）、douyin-automation、multi-platform-publish、wechat-mp-agent、tavily-search、self-improving-agent，加 docx/xlsx/pptx/pdf。这正是「外部能力缺口」的答案。
3. **技能市场（clawhub）5 个 IPC + bundles.json 分类**：原版能按 bundle 推荐安装 40+ 技能；只装 17 个固定员工不算完全复刻。
4. **runtime-cache 3438 文件**：离线运行时缓存（uv/python/playwright），决定断网可用性，我们还没有。
5. **安装引导 cards**（installer/cards）：首次启动引导流，属 F1/F0，未排。
6. **语音能力**：vosk-browser + voice/BGM + 克隆样本 + talk-voice 插件 → 语音输入/克隆入口，从未排进任何模块。
7. **tads 腾讯广告 20 IPC**：完整投放域（人群包/计划/广告/日报），被 P2 砍掉，但它是原版在卖的功能。
8. **hostapi:fetch / bi:geo-locate / log(5)**：主进程代理与诊断日志，缺了客服无法排障。
9. **asar-update 4 IPC**：只更新 asar 的轻量更新通道，稳定性关键。
10. **没有回归基线**：至今没有一份「原版行为录制」（请求/响应样本），P1 必须把关键接口响应落盘，否则「忠实」无从判定。
