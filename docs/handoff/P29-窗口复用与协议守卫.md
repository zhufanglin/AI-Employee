# P29 平台窗口复用 + 并行登录态检查 + 拦掉外部协议弹窗

版本：0.1.15　状态：已实现（待打包）

## 用户反馈（m14357）
1. 「BitBrowser:是系统弹窗,提示我去微软store下载」——不是我们代码里的功能，是平台页面里的「打开客户端」类链接
   调用了自定义协议（`snssdk://`、`xhsdiscover://`、`weixin://` 等），Chromium 交给 Windows 外部协议处理，
   Windows 找不到注册的应用就弹出「在 Microsoft Store 中查找应用」。
2. 「打开三个应用的弹窗有点慢」。

## 改法
### 1. 拦掉非 HTTP(S) 协议（`packages/desktop/src/main/platform.ts`）
- `const ALLOWED_SCHEME = /^(https?|wss?|data|blob|about|chrome-extension|devtools|file):/i`
- `ensureSchemeGuard(partition, ses)`：每个 partition 只挂一次 `ses.webRequest.onBeforeRequest`，
  命中白名单放行，其余 `callback({ cancel: true })` 并写日志 `[guard] 拦截外部协议请求：…`。
- 注意必须放行 `ws/wss`（平台页面长连接）、`data/blob/about`（页面自身），否则会把页面搞坏。

### 2. 常驻窗口池（原来每次操作都 `new BrowserWindow` + `destroy()`，冷启动 + 建渲染进程是主要耗时）
- `private readonly windows = new Map<string, BrowserWindow>()`，每个平台最多一个窗口。
- `ensureWindow(platform, show)`：池里有活的窗口就复用（需要可见时 `show()`+`focus()`），否则新建并登记；
  窗口被用户点 X 关掉时由 `closed` 事件自动从池里移除。
- `closeWindow()` 语义改为 **隐藏**（`win.hide()`）；新增 `destroyWindow()` 与 `disposeAll()`。
  退出登录走 `destroyWindow`（旧会话不能留着渲染），应用 `before-quit` 调 `platform?.disposeAll()`。
- `webPreferences.backgroundThrottling: false`：隐藏窗口也要正常跑定时器，否则取数/登录态检查会被节流拖慢。

### 3. 预热 + 并行
- `warmUp(platform?)`：提前 `ensureWindow(false)` 并导航到 `loginUrlHint`，不阻塞界面。
  新 IPC `platform:warm`，preload `platform.warm()`，发布页 `useEffect` 进入时先调它 —— 点「扫码登录」时窗口已经热好。
- `status()` 三个平台改 `Promise.all` 并行（锁是按平台分的，串行是慢的主因之一）。
- 登录态渲染等待从「10 轮 × 1s」改为「8 轮：首轮 600ms、之后 900ms」，文本超过 120 字即判定渲染完成。

## 已知限制
- 常驻隐藏窗口会占内存（每个平台一个渲染进程，空闲时很小）；平台页面若自行弹 `window.open` 已被 `setWindowOpenHandler` 拒绝。
- 真机效果（弹窗不再出现、速度提升多少）需用户在客户端实际点一次才能确认。
