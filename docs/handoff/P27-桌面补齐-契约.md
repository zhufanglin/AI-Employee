# P27 桌面补齐：契约（文件管理 + 定时任务）

> 目标：把 F2 缺口里的 A 级首簇 `file:*` 与 `cron:*` 在桌面端补上（原生有、我们没有）。
> 纪律：子 Agent **只新建自己名下的文件**，不要改 `main/index.ts`、`preload/index.ts`、`Shell.tsx`、`types.ts`、`package.json`、`scripts/verify.ps1`、`capability.service.ts`、`tool-loop.mjs`——这些由 Lead 统一接线。

## A. 文件管理（负责人：子 Agent A）

### 主进程模块 `packages/desktop/src/main/file-ops.ts`
```ts
import type { IpcMain } from 'electron'
export function registerFileOps(ipc: IpcMain, deps: { root: () => string }): void
```
- `root()` 返回工作区根目录（Lead 传 `<userData>/workspace`）。所有入参路径 `path.resolve` 后必须 `startsWith(root)`，否则抛中文错误 `路径超出工作区范围`。
- 只处理文件名层，禁止跟随符号链接逃逸；目录不存在时自动 `mkdirSync(recursive)`（写入类操作）。

IPC 通道（`ipcMain.handle`）：

| 通道 | 入参 | 返回 |
|---|---|---|
| `files:list` | `{ dir?: string }`（缺省 = root） | `{ ok: true, dir, items: [{ name, path, isDir, size, mtime }] }` 按目录优先、名称升序 |
| `files:read` | `{ path: string, maxBytes?: number }`（默认 200000，上限 2MB） | `{ ok: true, path, text, truncated }`；非文本（二进制判定：含 \u0000）返回 `{ ok: false, error: '这个文件不是文本文件，请用「打开」交给系统程序' }` |
| `files:write` | `{ path, text }` | `{ ok: true, path, size }` |
| `files:mkdir` | `{ path }` | `{ ok: true, path }` |
| `files:rename` | `{ path, name }` | `{ ok: true, path }`（`name` 不允许含路径分隔符） |
| `files:delete` | `{ path }` | `{ ok: true }`（目录用 `rmSync(recursive)`；目标是 root 本身必须拒绝） |
| `files:reveal` | `{ path }` | `{ ok: true }`（`shell.showItemInFolder`） |
| `files:open` | `{ path }` | `{ ok: true, error?: string }`（`shell.openPath` 返回的空串表示成功） |

### 渲染页面 `packages/desktop/src/renderer/src/pages/Workspace.tsx`
- 通过 `window.fcm.files`（Lead 会在 preload 暴露）调用上面通道；`files` 六个方法名：`list / read / write / remove / mkdir / open`，另有 `reveal`。
- UI：左侧面包屑（从工作区根往下点）、文件表格（名称/大小/修改时间）、右侧预览（文本只读）、顶部按钮「新建文件夹」「新建文件」（调用 `write`）、「打开」「在文件夹中显示」「删除」（删除要二次确认文案）。
- 中文界面，风格与 `PlatformPublish.tsx` 一致（`.card`/`.pill`/按钮类名沿用 `styles.css` 已有类；新增样式只能写在本页内联或新加 `workspace-*` 前缀，不要改 `styles.css`）。

## B. 定时任务（负责人：子 Agent B）

### 主进程模块 `packages/desktop/src/main/cron-ops.ts`
```ts
import type { IpcMain } from 'electron'
export function registerCronOps(ipc: IpcMain, deps: { api: (path: string, init?: any) => Promise<any> }): void
```
- `deps.api` 是 Lead 传进来的已带 JWT 的 HTTP 封装（`api('/capabilities/run', { method:'POST', body: JSON.stringify({ name, params }) })`）。
- 能力契约（服务端已上线，**注意 201 + `success:false` 表示失败**）：
  - `cron_create`：`{ employeeSlug, cronExpr, timezone, workflowKey?, title? }` → `{ cronId, nextRunAt }`
  - `cron_list`：`{}` → `{ items: [{ cronId, employeeSlug, cronExpr, timezone, enabled, nextRunAt, lastRunAt }], total }`
  - `cron_delete`：`{ cronId }` → `{ deleted: true }`
- 通道：`cron:list`（无参）、`cron:create`（`{ employeeSlug, cronExpr, timezone, workflowKey?, title? }`）、`cron:delete`（`{ cronId }`）。返回值统一 `{ ok, data?, error? }`，错误取 `body.error` 中文文案。

### 渲染页面 `packages/desktop/src/renderer/src/pages/Scheduled.tsx`
- 通过 `window.fcm.cron`（Lead 接线）调用：`list / create / remove`。
- UI：表格（员工 / 表达式 / 时区 / 下次运行 / 状态 / 删除）、新建表单（员工 slug、cron 表达式，附 3 个常用示例按钮：「每天 9 点」`0 9 * * *`、「每周一 10 点」`0 10 * * 1`、「每小时」`0 * * * *`、时区默认 `Asia/Shanghai`）、错误红字展示服务端中文原文。
- 中文界面，风格同上。
