# T-29 运营后台 Web 控制台（零构建静态 SPA）

完成时间：2026-11-05 · 负责人：dsh-lead

## 为什么是零构建

原版后台是独立的 admin web 前端（Web 管理端，238 条 /admin 路由的主体）。复刻这边后端 77 条 admin API 已就绪（T-14），缺的只是界面。
为了不再引入一条 Vite/React 构建链（多一个 node_modules、多一份打包配置、多一处发版步骤），后台做成**纯静态 SPA**，由 Nest 同源托管：

```
packages/server/public/admin/
├── index.html   # 骨架，只有 <div id="app">
├── styles.css   # 深色主题（与原版控制台观感对齐）
└── app.js       # 约 24KB，无框架，8 个视图 + 通用表单/分页/提示
```

访问：`http://<服务端地址>/admin/`（与 API 同源，端口同 `PORT`，默认 3000）。
登录走 `POST /api/auth/admin/login`（`ADMIN_USERNAME` / `ADMIN_PASSWORD`，默认 admin/admin），token 存 localStorage 键 `fcm_admin_token`，401 自动回到登录页。

## 路由托管（唯一后端改动）

`packages/server/src/main.ts`：

```ts
app.use("/admin", serveStatic(join(__dirname, "..", "public", "admin"), { maxAge: "0", fallthrough: true }));
```

要点：
- 必须用 `__dirname`（编译后是 `packages/server/dist`），不能用 `process.cwd()` —— 后台是随代码走的，不是运行时产物；
- 与 `/uploads` 静态服务并列，都注册在 `setGlobalPrefix("api")` 之前，因此不受 `/api` 前缀影响；
- `/admin` 无尾斜杠时 express 会 301 到 `/admin/`；
- **部署注意**：打服务端部署包时必须把 `public/` 一起打包（早期 staging 包只含 `dist prisma package.json`，需要补 `public`）。

## 视图与对应 API

| 视图 | 能力 | 接口 |
|---|---|---|
| 概览 | 9 张指标卡 + 模型用量表 | `GET /admin/overview`、`GET /admin/usage/summary` |
| 订单 | 按状态/关键字筛选、分页、待支付「确认收款」 | `GET /admin/orders`、`POST /admin/orders/:orderNo/confirm` |
| 用户 | 搜索、调积分（正数赠送/负数扣减）、启用禁用、重置密码 | `GET /admin/users`、`PUT /admin/users/:id/credits\|status\|password` |
| 积分套餐 | 列表、新建、改积分与价格（元入参，服务端按分存）、下架 | `GET\|POST /admin/packages`、`PATCH\|DELETE /admin/packages/:id` |
| 兑换码 | 按状态筛选、批量生成（套餐/数量/有效天数）、禁用、删除 | `GET\|POST /admin/redemption-codes`、`PUT\|DELETE /admin/redemption-codes/:id` |
| AI 员工 | 17 个员工列表、改价（积分/天 + 展示文案）、上下架 | `GET /admin/employees`、`PUT /admin/employees/:id`、`PUT /admin/employees/:id/toggle` |
| 定价 | 模型按次价、媒体任务价直接改 | `GET\|POST /admin/model-pricing`、`GET\|POST /admin/media-pricing` |
| 站点配置 | 站点名/免费额度/客服二维码等 + AI 接口配置（密钥显示 ****） | `GET\|PUT /admin/site-config`、`GET\|PUT /admin/ai-api-config` |

表单是用 `genericForm(obj)` 从接口返回对象自动生成的（跳过 `volcengineModels/updatedAt/createdAt/id`），所以后端加字段前台自动出现，不用改前端。含密钥字段由后端 `mask()` 脱敏成 `****`，原样提交即「不修改」。

## 验证

### 1) 冒烟 `scripts/smoke-admin-ui.mjs`（已并入 `verify.ps1 -Smoke`，11 项全绿）
- `GET /admin/` 200 且含「运营后台」、引用 `app.js`；
- `/admin/app.js` 200 且含 `fcm_admin_token` 与 `/admin/overview`；`/admin/styles.css` 200 且含 `.layout/.panel`；
- `GET /admin` 301/200；
- 未带令牌 `GET /api/admin/overview` → 401；
- 管理员登录 201 且返回 accessToken；
- 带令牌 `GET /api/admin/overview` 200 且含 `users` 数字；`GET /api/admin/site-config` 200。

### 2) 真浏览器验证 `scripts/shot-admin.mjs`（CDP 驱动 Edge headless）
做法：API 登录拿 token → `--headless=new --remote-debugging-port` 起 Edge → CDP 注入 `localStorage` token → 逐个 tab 点击 → 截图 + 收集 `Runtime.exceptionThrown` / console error。
实测结果（2026-11-05）：
- 概览页真实数据渲染正常：用户总数 120、今日新增 98、累计营收 ¥66.00、模型用量 58 次 / 45916 tokens / 扣费 13 积分；
- 订单 33 条、用户 120 人（6 页）、AI 员工 17 个、定价、站点配置均正常出表；
- **0 个 JS 异常、0 条 console error**；
- 截图产物：`_admin_overview.png`、`_admin_orders.png`、`_admin_users.png`、`_admin_employees.png`、`_admin_pricing.png`、`_admin_site.png`（仓库根，属验证产物）。

命令：`node scripts/shot-admin.mjs`（需服务端在 :3000 运行；脚本会自己起停 Edge）。

## 与原版的差距（已知）

| 项 | 原版 | 复刻 |
|---|---|---|
| 页面数量 | 88 条 admin 路由，多标签完整后台 | 8 个视图，覆盖日常运营必需（用户/订单/套餐/兑换码/员工/定价/站点/用量） |
| 站点配置细分 | 短信/OSS/微信支付/系统信息各有专属表单 | 通用表单自动生成（可用但不够精致）；`sms-test`、`upload-*`、`statistics/*` 已有 API 未接界面 |
| 权限 | 多角色 | 仅 `admin` 单角色（`@Roles("admin")`） |
| 构建 | React + 打包 | 无构建，改完刷新即生效 |
