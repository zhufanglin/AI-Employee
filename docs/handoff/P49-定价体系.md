# P49-定价体系（成本驱动，库内可改）

> 目标（用户 m24015）：价格按实际 API 模型成本推导，落在数据库里可改，代码里不写死金额。

## 1. 为什么原来的定价不能用

- 改造前 `ModelPricing` 11 行全是 `per_request / pricePerRequest=1`，即**任何模型、任何长度都收 1 积分**；`MediaPricing` 也是拍脑袋的 20/10/1.2 等值。
- 真实成本差异可达 10 倍以上（lite 0.6 元/百万 token 输入 vs pro 4.0 元/百万 token），一刀切 1 积分意味着**长上下文任务亏钱、短任务又收不上价**。
- 且计费键不匹配：调用方/用量记录传的是 `doubao-seed-2-0-lite`（横线、无版本号），定价行 `modelId` 是 `doubao-seed-2.0-lite`（点号）⇒ 精确 `findUnique` 查不到会**静默回落到 1 积分兜底**，改价等于没改。

## 2. 数据模型（prisma/schema.prisma）

| 表 | 新增字段 | 作用 |
| --- | --- | --- |
| `ModelPricing` | `upstreamCostInputPerMillionCny`(默认1.8)、`upstreamCostOutputPerMillionCny`(默认14.4)、`costNote` | 记录**上游真实成本**（元/百万 token），是建议价的唯一输入 |
| `MediaPricing` | `upstreamUnit`(`coins`/`cny`)、`upstreamCoinsPerUnit`、`upstreamUnitCostCny`、`costNote` | 记录上游单位成本（RunningHub 币数或人民币） |
| `PricingConfig`（新，单例 id=`global`） | `creditsPerYuan`(100)、`targetMarginPercent`(100)、`minCreditsPerRequest`(1)、`trialCredits`(200)、`mediaCoinCny`(0.01) | 全局商业参数，后台可改 |
| `PricingChangeLog`（新） | `scope`/`target`/`before`/`after`/`operator` | 每次改价留痕，可审计 |

迁移：`packages/server/prisma/migrations/20261113084608_pricing_config/migration.sql`。

## 3. 定价公式（packages/server/src/billing/pricing.service.ts）

```
模型：售价(积分/百万token) = ceil(成本(元/百万token) × (1 + 目标毛利/100) × 每元积分)
      单次收费 = max(最低积分, ceil(输入token/1e6×售价in + 输出token/1e6×售价out))
媒体：单位成本(元) = 上游币数 × mediaCoinCny  或  上游元/单位
      单次收费 = max(1, ceil(单位成本 × (1+毛利) × 每元积分))；按秒计价保留两位小数
```

计费口径三选一，老数据仍兼容：`per_request`（原版）、`per_token`（原版每千 token）、`per_token_million`（成本驱动，推荐）。

**模型标识容错** `findPricingRow(modelId)`：别名精确 → 上游 id → 去掉 `-260428` 这类日期后缀 → 归一化模糊（忽略大小写与 `. - _`）。`doubao-seed-2.0-lite` / `doubao-seed-2-0-lite` / `doubao-seed-2-0-lite-260428` 全部命中同一行。缓存 30s，后台改价/重算后 `clearCache()` 立即生效。

## 4. 后台用法（https://ai.fcmediaagent.com/admin/ → 定价）

1. 顶部「全局参数」：每元积分、目标毛利%、单次最低积分、新用户试用积分、RunningHub 币价 → 保存（写 `PricingChangeLog`）。
2. 模型表：填「上游成本 输入/输出（元/百万 token）」→ 显示「现价 / 建议价 / 按近 30 天实测每次多少积分、毛利多少倍」→ 单行保存或整表重算。
3. 媒体表：选成本单位（币/元）+ 数量 → 建议价。
4. 「重算」= `POST /admin/pricing/recalc`，`mode=preview` 只看差异，`mode=apply` 写库；幂等（再 preview 差异为 0）。

API：`GET /admin/pricing/overview?days=30`、`PATCH /admin/pricing/config`、`POST /admin/pricing/recalc`、`GET /admin/pricing/changelog`。

## 6. 生产实测（47.85.46.165，2026-11-13）

- 迁移：`prisma migrate deploy` 应用 `20261113084608_pricing_config`（共 17 个迁移）；`PricingConfig` 单例 `creditsPerYuan=100, targetMarginPercent=100, minCreditsPerRequest=1, trialCredits=200, mediaCoinCny=0.01`。
- 种子 + 重算：`DONE models=11 media=6`，`recalc apply applied=14`。生产现价（积分/百万 token）：lite 120/480、turbo 240/960、pro 与 deepseek-v3.2/v4-pro/kimi/minimax 800/3200、code 600/2400、glm-5.1 160/640。
- **计费实测**：员工任务 `boss-lead-radar` 一次模型请求 `6276 输入 + 793 输出` → `creditsCharged=2`、`pricingMode=per_token_million`，余额 116 → 114（`CreditTransaction` 一条 consume -2）。改造前同量级请求固定 1 积分。
- 媒体现价：`image_gen` 314 积分/次（成本 157 币×0.01 元×2 倍毛利）、`video_gen` 300、`lipsync` 46/秒。
- 冒烟：`scripts/smoke-p49-pricing.mjs` **39 项全绿**（公式、模型标识容错、配置校验、重算幂等、试用赠送端到端、留痕）。

## 7. 新用户试用积分

注册/首次短信登录成功 → `auth.service.ts` 调 `pricing.trialCredits()`（默认 200）→ `credits.addCredits(type='gift', description='新用户试用赠送（N 积分）')`，失败只 `logger.warn` 不阻断登录。200 积分 ≈ 一次 10 步任务的量级（每步约 2 积分），够体验 1–2 个任务。

## 8. 必须校准的三个数（等用户/账单）

1. **RunningHub 币价** `mediaCoinCny`（当前假设 1 币 = 0.01 元，即 100 币/元）。若实际充值比例不同，全套媒体价要按新值重算（后台改一个数 + 点「重算」）。
2. **火山方舟实际单价**（当前是公开价目档位，可能与合同价/阶梯价有差异）——拿到账单后改模型表的成本列再重算。
3. **兑换码/套餐的积分定价**（后台 `packages` 仍是占位值「小康 999 积分 / 1 元」），属商业决策，待用户拍板；`creditsPerYuan` 决定「1 元卖多少积分」。

## 9. 运维注意

- 改价后无需重启：后台保存/重算会 `clearCache()`；直接改库需等 30s 缓存过期。
- 「免费额度」`SiteConfig.freeMonthlyQuota`（默认 10 次/月）与积分是两条独立通路：额度内不扣积分，超额才扣。
- 员工任务按「每次模型请求」扣费，任务级 `creditsCharged` 恒为 0（不会重复记账）；若要让用户看到「这个任务花了多少积分」，需另做汇总字段。
- 重算只写 `ModelPricing` / `MediaPricing`，不动 `PricingConfig`；全局参数改动也会记 `PricingChangeLog(scope='config')`。
