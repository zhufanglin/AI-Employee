# P25 平台作品数据快照（+ P27 桌面补齐接线）

> 起因：P24 平台发布上线后，用户授权的下一步是「我来自测」与「和你的 Agent 一起把桌面缺的补齐」。
> 本轮做三件事：①平台作品数据取数（P25）②登录态假阳性修正 ③把 P27 的文件管理/定时任务页接到客户端。

## 一、P25：为什么「取数」不做字段映射

三个平台的数据后台都是动态组件，字段名和 DOM 结构常改。硬编码 `.xxx-number` 选择器，
平台一改版就全废，而且写错还不如不写（悄悄返回 0 比报错更危险）。

做法：打开平台自己的「作品数据」页 → 等页面渲染 → 抓 `document.title` / `location.href` /
`document.body.innerText`（压缩空行、截断上限 12000 字）→ 原样返回给用户/员工看，
由模型自己从这段自然语言里读数字。

| 项 | 做法 |
| --- | --- |
| 页面 | douyin `/creator-micro/data/content`、xiaohongshu `/new/statistics/data`、shipinhao `/platform/statistics`（打不开时回落首页） |
| 登录判断 | 先找否定证据（页面有二维码/「登录」字样、URL 命中 login/passport/signin），再找肯定证据（`loggedInCues` 文案命中正文、登录 cookie 存在、页面有昵称），都没有就判**未登录** |
| 返回 | `PlatformStatsSnapshot`：`{ platform, name, ok, loggedIn, pageTitle, href, text, screenshots, message }` |
| 截图 | 每次取数落一张 `platform-logs/<platform>-<ts>-stats.png`，失败也有 `-stats-login.png` |
| 上限 | `maxChars` 默认 4000，夹在 500–12000 |

## 二、登录态假阳性（P24 遗留的真 bug）

P24 交付后我用 Electron 探针直连真实平台，`status()` 报抖音「已登录」，但把上传页打开是**扫码登录页**。
根因在 `packages/desktop/src/main/platform.ts` 的 `judgeLogin()`：最后一句是
`return { loggedIn: true, nickname }`——页面还没渲染完（body 为空）时既读不到登录词也读不到二维码，
于是全部落到「默认已登录」。`checkStatus()` 又只 `sleep(3000)` 就读，冷启动根本不够。

两处修：

1. `judgeLogin()` 改成「先否定后肯定，都没有就判未登录」，末尾一行注释写明为什么不是 true。
2. `checkStatus()` 去掉固定 3 秒等待，改为最多 10 轮、每轮 1 秒读探针，读到登录线索或正文 > 200 字即停。

实测（本机 Electron 探针，真实抖音页）：

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| `status('douyin')` | `loggedIn: true`（假） | `loggedIn: false` + 「请点扫码登录」 |
| `stats('douyin')` | 不存在 | 14.8s 返回 `ok:false / loggedIn:false` + 中文提示 + 登录页截图 |

## 五、UI 上要知道的两件事

- 平台卡片的状态来自真实页面判定，现在**不会再出现「显示已登录、点发布才发现要扫码」**。
- 「数据快照」不做定时刷新、不落库：点一次读一次，数据页文案直接给用户看，也可以整段贴给员工做复盘。
