# P28 登录态检查缓存（切页面不再重查）

## 用户反馈（m14185）
> 老是显示没有下载 BitBrowser；实测出一个 bug：我等待刷新登录状态之后切换页面，它又会重新检查，这导致要我继续等

（BitBrowser 那半句在代码库里 grep 不到任何相关字符串，待用户确认出处。）

## 根因
`packages/desktop/src/renderer/src/pages/PlatformPublish.tsx` 里的 `useEffect(() => { void refresh() }, [])` 会在**每次进入「📤 平台发布」页**时调用 `window.fcm.platform.status({})`；
而主进程 `packages/desktop/src/main/platform.ts` 的 `status()` 对每个平台都**开一个隐藏窗口 → 导航到创作后台 → 轮询最多 10 秒等页面渲染 → 读探针**，三个平台串行 ≈ 10–20 秒。
所以「刷新登录状态」等完之后切走再回来，等于从头再查一遍，用户又得等。

## 修法（0.1.14）
1. **主进程缓存**：`platform.ts` 新增 `export const STATUS_CACHE_MS = 5 * 60 * 1000` 与 `private readonly statusCache = new Map<string, { at: number; status: PlatformStatus }>()`。
   - `status(platform?, { maxAgeMs })`：默认 `STATUS_CACHE_MS`，命中缓存直接返回，不再开窗口；`maxAgeMs: 0` 强制重查。
   - `checkStatus()` 拆成「查一次 `checkStatusFresh` + 写缓存」；`页面没有响应` / `登录态检查失败` 这类不确定结果 **不写缓存**（`uncertain` 正则 `/没有响应|检查失败/`），下次仍会重查。
   - `logout()` 清掉该平台缓存。
2. **IPC 透出强制重查**：`platform:status` 接受 `{ platform?, force? }`，`force` → `maxAgeMs: 0`（`packages/desktop/src/main/index.ts:395`、`preload/index.ts`、`renderer/src/types.ts`）。
3. **渲染层再缓存一层**：`PlatformPublish.tsx` 用模块级 `statusMemo` + `rememberStatus()`（`RENDERER_CACHE_MS` 5 分钟），页面挂载时先用缓存直接渲染，**不发 IPC**；「刷新登录状态」按钮走 `refresh(true)` → `{ force: true }`，期间文案「检查中…（约 10 秒）」。
   - 卡片新增一行「检查时间：HH:MM:SS」（来自 `checkedAt`），用户能看出这是缓存结果而不是新查的。

## 已知限制
- 缓存是「内存 + 5 分钟」，关掉客户端重开就重查一次（这是应有行为）。
- 若用户在别处（比如同一 partition 的调试窗口）改了登录态，最多滞后 5 分钟；点「刷新登录状态」可立刻重查。
- 「数据快照」「开始发布」不受缓存影响，仍然每次都真开窗口。
