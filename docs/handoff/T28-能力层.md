## 顺手修掉的真 bug（重要）
`packages/server/src/toolapi/toolapi.service.ts` 的 `aiText(phone, content, model?)` 原来把 **phone 当成 userId** 传给 `compute.processComputeRequest()`：
- 后果：credits / quota / AiUsageRecord 全部按一个不存在的 userId 读写，抛出的异常 message 为空 → 上层只看到「失败但没原因」；toolapi 里的 AI 早报、话术生成等能力全部受同一影响。
- 修法：先 `prisma.user.findFirst({ where: { phone }, select: { id, status } })`，不存在抛「账号不存在」、非 active 抛「账号已被禁用」，再用 `account.id` 走计费链路。
