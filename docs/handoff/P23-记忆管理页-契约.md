# P23 记忆管理页 + 服务端记忆接口（契约）

> 目的：桌面端能"看得见、能删、能手动合并"长期记忆。服务端补一组 REST 接口，桌面端加一个页面。
> 本文件是**接口契约**，服务端与桌面端并行开发，双方都必须遵守。

## 一、服务端 REST（前缀 /api，JWT 用户态）

所有接口都用全局 JWT 守卫，用户身份取 `req.user`（对象里至少有 `id`、`phone`），
**所有查询/删除必须按 `userId = req.user.id` 隔离**，越权一律当作不存在（404）。

### 1) GET /api/memory/list
Query：`query`（可选，模糊匹配 title/content/tags）、`kind`（可选，note|fact|preference|lesson）、`limit`（1–50，默认 20）、`cursor`（可选，上一页最后一条的 id）。

返回：
```json
{
  "items": [
    {
      "id": "cmw...",
      "kind": "fact",
      "title": "赵姐报价口径",
      "content": "只接受季度付，报价必须含税，报关走宁波港",
      "tags": ["报价", "客户"],
      "employeeSlug": null,
      "sourceTaskId": null,
      "hitCount": 3,
      "createdAt": "2026-11-08T09:55:57.022Z",
      "updatedAt": "2026-11-08T09:55:57.022Z"
    }
  ],
  "nextCursor": null,
  "total": 12
}
```
- 排序：`createdAt DESC, id DESC`；keyset 分页（cursor = 上一页最后一条 id，取它的 createdAt+id 作为界）。
- `total` = 当前筛选条件下该用户的总条数（用 `count`）。
- `tags` 在库里是逗号分隔字符串，返回**数组**（空字符串 → `[]`）。

### 2) GET /api/memory/stats
返回：
```json
{ "total": 12, "byKind": { "note": 4, "fact": 5, "preference": 2, "lesson": 1 }, "last7d": 3, "topTags": [{ "tag": "报价", "count": 3 }] }
```
- `topTags` 最多 8 个，按出现次数降序。
- `last7d` = createdAt 在最近 7 天内的条数。

### 3) DELETE /api/memory/:id
- 成功：`{ "success": true, "id": "cmw..." }`
- 不是自己的或不存在：**404**，message「记忆不存在或不属于你」
- 返回 200（不要在 DELETE 上返回 201，控制器加 `@HttpCode(200)` 不必要，DELETE 默认 200）

### 4) POST /api/memory/merge
Body：`{ "keepId": "cmw...", "dropId": "cmw..." }`
- 两条都必须属于当前用户；`keepId !== dropId`，否则 400「keepId 与 dropId 不能相同」
- 合并策略：保留 **createdAt 更早** 的那条作为最终保留条（即使调用方传反了，也要以更早的为准，返回实际保留的 id）
- 合并后的内容：优先用 LLM 合并（`judgeMemory(providers, keep.content, [{id: drop.id, title: drop.title, text: drop.content}])`，**仅当 relation === "merge" 且返回 merged 时采用**），否则退化为 `keep.content + "\n" + drop.content`（截 4000 字）
- tags 取并集（逗号分隔、去重、总长 ≤512）；hitCount = 两者之和；title 保留 keep 的（若 keep.title 为空则用 drop.title）
- 落库：`update` keep + `delete` drop，两步在同一 `$transaction` 里
- 返回：`{ "id": "<保留条 id>", "content": "...", "tags": ["..."], "hitCount": 5, "mergedFrom": ["<drop id>"], "usedLlm": true }`
- 返回 200（`@HttpCode(200)`）

### 5) POST /api/memory/dedupe
Body：`{ "mode": "report" | "apply", "limit": 30 }`（mode 缺省 apply，limit 1–60 缺省 30）
- 直接委托 `CapabilityService.run({ id: req.user.id }, "memory_dedupe", { mode, limit })`
- 返回该能力的 `data`（原样）：`{ mode, total, scanned, calls, applied, truncated, durationMs, proposals: [...] }`
- 返回 200（`@HttpCode(200)`）

## 二、桌面端 IPC（preload 暴露 `window.fcm.memory`）

主进程用现成的 `api(path, init)` 帮助函数（`packages/desktop/src/main/index.ts:52`，自动带 token）。

| IPC channel | preload 方法 | 转发到 |
| --- | --- | --- |
| `memory:list` | `memory.list({ query?, kind?, limit?, cursor? })` | `GET /memory/list?...` |
| `memory:stats` | `memory.stats()` | `GET /memory/stats` |
| `memory:remove` | `memory.remove(id)` | `DELETE /memory/:id` |
| `memory:merge` | `memory.merge({ keepId, dropId })` | `POST /memory/merge` |
| `memory:dedupe` | `memory.dedupe({ mode, limit })` | `POST /memory/dedupe` |

## 三、桌面页面要求（renderer）

新增 `packages/desktop/src/renderer/src/pages/Memory.tsx`，并在 `Shell.tsx` 侧栏加一项 **🧠 记忆**（放在「📊 积分与用量」上方/下方均可，不要放进「高级/实验」折叠区）。

页面必须包含：
1. 顶部：标题「记忆」+ 一行统计（总数 / 各类型数量 / 最近 7 天），数据来自 `memory.stats()`
2. 搜索框（回车或点击搜索，300ms 防抖可选）+ 类型筛选（全部 / 笔记 / 事实 / 偏好 / 经验）
3. 记忆列表：每条显示 title（可空则显示内容前 20 字）、content（默认 3 行截断，可展开）、tags 小标签、`kind` 中文名、创建时间（`toLocaleString`）、`hitCount`；每条有「删除」按钮（`window.confirm` 二次确认）；列表支持「加载更多」（nextCursor）
4. 多选合并：每条左侧 checkbox，选中恰好 2 条时浮出「合并所选 2 条」按钮 → `memory.merge`，成功后刷新列表并提示
5. 「查重」按钮：先 `dedupe({ mode: "report" })` 展示建议（保留/删除标题、相似度、合并预览），再提供「立即合并（执行）」按钮调 `dedupe({ mode: "apply" })`；执行后刷新
6. 空状态（「还没有记忆，员工在任务里说的客户偏好会自动记下来」）与错误态（接口失败显示后端 message，401 提示重新登录）
7. 不用新增第三方依赖；样式写在 `styles.css`（用现有卡片/按钮 class 风格，允许新增少量 class）
