### A1. 员工产物统一登记（最高优先，SV-10 / SV-11 / SV-12 / UI-11）

**问题**：`packages/worker/tool-loop.mjs:173` 只对 `tool === 'file_write'` 且返回 `{key,name}` 时 push 到 `files`，最终由 `packages/worker/cloud-executor.mjs:195` 写成 `workspace-file` artifact。于是 `doc_write`、`transcribe`、`media_process` 生成的文件落在工作区，但**不进任务产物列表**，用户必须自己去资料库翻。

**三种返回形态（我已核对源码）**：
- `file_write`：`{ key, name, bytes, url }`（顶层）
- `doc_write`（`packages/server/src/capabilities/capabilities/docs-write.ts:313,321`）：`{ name, bytes, key, url, format, ... }`（顶层，同样是 key+name）
- `transcribe`（`packages/server/src/capabilities/capabilities/asr.ts:235`）：`result.file = { name, key, bytes, url }`（**嵌套在 file**）
- `media_process`（`packages/server/src/capabilities/capabilities/media-tools.ts:436-441` 走 `saveWorkspaceFile`）：返回值里带落盘文件信息（你自己读该文件确认真实字段名，可能是 `file` 或顶层 key/name，按实际写）

**做法**：抽一个 `collectFiles(result)` 归一化函数，覆盖「顶层 key+name」「嵌套 `result.file`」「media_process 的落盘结构」三种，push 时去重（同 key 只留一次）。**不要**把 OSS 的 `url` 当下载凭据暴露给无权限者——artifact 仍用 `{kind:'workspace-file', path:key, name}` 形态，下载走既有鉴权。

**验收**：
- 新增 `scripts/smoke-p47-artifacts.mjs`：直接 require `dist` 的 `collectFiles`（或 tool-loop 导出），断言三种形态都能归一化、重复 key 去重、无 key 的返回不 push。
- 真机/接口级：跑一条会产 doc_write 的员工任务，`GET /employee-tasks/:id` 的 `artifacts` 里出现该文件（这条可以写成需要跑测试账号的 smoke，或写清手工验证步骤）。
