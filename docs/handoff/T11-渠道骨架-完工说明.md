## 二、接口清单

全局前缀 `/api`。回调类接口带 `\@Public()`（微信服务器无法带 JWT）；`status` / `send` 是内部接口，仍受全局 `JwtAuthGuard` 保护。

### 企业微信 `/api/channels/wecom`

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/callback` | URL 验证。参数 `msg_signature/timestamp/nonce/echostr`；`echostr` 是**密文**，按 `sha1(sort([token,timestamp,nonce,echostr]).join(""))` 验签后 AES 解密，返回明文 echostr（`text/plain`）。未配置返回「渠道未配置」 |
| POST | `/callback` | 接收消息。同套验签；解 `<Encrypt>` → 校验 receiveid==CorpID → 解析 XML → 调度 → 5 秒内返回**加密**被动回复 XML（`ToUserName`/`FromUserName` 互换），`\@HttpCode(200)` |
| POST | `/send` | 内部发文本应用消息，body `{ touser, msgtype:"text", text:{ content } }`，调 `https://qyapi.weixin.qq.com/cgi-bin/message/send?access_token=` |
| GET | `/status` | `{ configured, corpid, agentId(脱敏), hasToken, hasAesKey, hasSecret, lastCallbackAt }` |

access_token：`GET https://qyapi.weixin.qq.com/cgi-bin/gettoken?corpid=&corpsecret=`，进程内缓存 `expires_in`，**提前 300 秒**刷新；并发请求复用同一个 Promise；业务错误码 **40014 / 42001** 清缓存重试一次。

### 微信公众号 `/api/channels/wechat-mp`

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/callback` | 服务器校验。有 `msg_signature` 且配置了 `WECHAT_MP_AES_KEY` 时走安全模式（解密 echostr）；否则明文 `signature = sha1(sort([token,timestamp,nonce]).join(""))`，相等则原样返回 echostr |
| POST | `/callback` | 安全模式：`msg_signature`（含 Encrypt）验签 + AES 解密（receiveid=AppID）→ 解析 text/event/image/voice → 5 秒内加密被动回复；无 `msg_signature` 时按明文模式回明文 XML。事件支持 subscribe / unsubscribe |
| POST | `/send` | 客服消息，body `{ touser(openid), msgtype:"text", text:{ content } }`，调 `https://api.weixin.qq.com/cgi-bin/message/custom/send?access_token=` |
| GET | `/status` | `{ configured, appId, hasToken, hasAesKey, hasAppSecret, lastCallbackAt }` |

access_token：`https://api.weixin.qq.com/cgi-bin/token?grant_type=client_credential&appid=&secret=`，同样的缓存/并发去重；错误码 **40001 / 42001** 清缓存重试一次。

### 加解密实现要点（协议来源）

- 企业微信加解密方案：<https://developer.work.weixin.qq.com/document/path/90968>；回调协议：<https://developer.work.weixin.qq.com/document/path/90930>
- 公众号消息加解密：<https://developers.weixin.qq.com/doc/offiaccount/Message_Management/Message_encryption_and_decryption_instructions.html>
- `AESKey = Base64Decode(EncodingAESKey + "=")`（43 位 → 32 字节），AES-256-CBC，`IV = key[0..16]`
- 明文结构：`16 字节随机串 + 4 字节网络序 msg_len + msg + receiveid`（企微 receiveid=CorpID，公众号=AppID）
- **PKCS#7 块大小 32**（不是 16），这是最容易写错的地方
- 签名：`sha1(sort([token, timestamp, nonce, Encrypt]).join(""))`；URL 验证时最后一项是 echostr 密文
- 不引入第三方库，全部基于 `node:crypto`

## 三、消息路由与异步推送（dispatcher.service.ts）

1. 收到文本 → 解析渠道用户 → 找平台 `userId`；
2. 有 `CHANNEL_EMPLOYEE_SLUG`（默认 `boss-lead-radar`）且有 userId：调用 **`EmployeeService.run(userId, slug, { executor:"cloud", title, input })`** 创建云端任务（现有唯一可创建任务的公开方法，见下方降级项）；
3. 立即返回 ACK：「已收到，正在处理，稍后把结果发给你」，满足 5 秒被动回复窗口；
4. **第一版轮询，后续换事件**：`setInterval` 每 5 秒查 `employeeTask`，最长 10 分钟；`succeeded` 推送结果（优先 `outputText`，其次 `employeeTaskArtifact.text`），`failed` 推送失败原因，超时推送超时提示；`needs_input` / `awaiting_approval` 停止轮询并提示去后台处理；
5. 推送通过 `/send` 对应的 service 方法主动发出；文本截断保护：企微 600 字（2048 字节上限）、公众号 1800 字（2048 字上限）。
6. 没配员工 slug → 回「渠道未配置」并写 warn 日志；没配凭证 → `status` 显示未配置、回调返回「渠道未配置」。

## 六、未完成 / 降级项（重要）

1. **渠道用户 → 平台 userId 绑定缺失（最大缺口）**
   - `EmployeeExecutionService` 现有公开方法只有 heartbeat / nodes / claimCloudTasks / recover / taskHeartbeat / nodeHeartbeat，**没有创建任务的方法**，且 `EmployeeModule` 未导出它；因此改用 `EmployeeService.run(userId, slug, body)`。
   - `EmployeeService.run` 需要真实 `userId`：企微成员 UserID 在现有 Prisma schema 里没有映射字段（未改库）；公众号可用 `User.wechatOpenId` 反查。
   - 当前策略：优先 `CHANNEL_OWNER_USER_ID`（所有渠道消息归到一个账号），其次公众号按 openid 反查；企微没有对应关系时**只回「已收到」并写 TODO 日志**，不硬改员工链路。要真正多用户可用，需要新增「渠道身份映射表」（如 wecom userid / openid → userId），或给 User 加 wecom userid 字段。
   - `EmployeeService.run` 还会校验员工已上架、用户有对应套餐/购买记录/安装记录；任一不满足会抛 ForbiddenException，此时同样降级回「已收到」并记 warn，不会把 500 抛回微信。

2. **异步结果靠轮询**：5 秒间隔、最长 10 分钟，进程重启会丢轮询。后续应换事件/队列（代码已留注释与 `watchTask` 单点入口）。

3. **status / send 接口受全局 JWT 保护**：微信服务器只打 callback，这两个是内部接口。若运维希望匿名探活，需再加 `\@Public()` 或网关白名单。

4. **被动回复只回 ACK 文本**：5 秒内无法完成 AI 任务，结果一律异步推送；企微/公众号被动回复超时会重试，因此回调必须快速返回。

5. **未做**：图片/语音/文件消息的内容下载与转存（当前只回提示文本）；`MsgId` 幂等去重（微信超时重试可能重复建任务）；多实例 access_token 共享（进程内缓存，多副本各自取 token，注意 gettoken 频率限制）；公众号明文模式仅兼容，不推荐生产使用。

6. **未接真实凭证，未做真实回调联调**：所有签名/加解密用假凭证按官方算法互相验证，尚未与微信服务器实际握手。

## 七、拿到凭证后还需要做什么

1. 在 `packages\server\.env` 填入第四节全部 env（EncodingAESKey 用微信后台生成的 43 位，不要自己造）。
2. 微信后台配置回调 URL：
   - 企微自建应用 → 接收消息 → URL 填 `https://<域名>/api/channels/wecom/callback`，Token/AESKey 与 env 一致；
   - 公众号 → 服务器配置 → URL 填 `https://<域名>/api/channels/wechat-mp/callback`，Token/AESKey（安全模式）一致，消息加解密方式选「安全模式」。
3. 公网 HTTPS 可达，且反向代理放行 POST 的 `text/xml` 原始报文（不要提前解析/改写 body）。
4. 准备一个可用的平台账号：配置 `CHANNEL_OWNER_USER_ID`，或补渠道身份映射表；确认 `boss-lead-radar` 员工已上架、该账号已购买/安装，否则只会回「已收到」。
5. 联调顺序：先点微信后台「保存」验证 GET 回调（看 status 的 `lastCallbackAt` 与日志），再发一条文本消息确认 ACK，最后确认 5 秒~任务完成后能收到主动推送；同时核对 `GET /api/channels/wecom/status` 与 `/api/channels/wechat-mp/status` 的 `configured/hasToken/hasAesKey` 是否符合预期。
