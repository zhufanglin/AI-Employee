# P38 视频号评论读通（脏表单把导航全拦掉）+ 0.1.22

## 1. 现象
用户在客户端装好 0.1.21 后，视频号已扫码登录，但「视频号评论」读不出东西：

```
{"ok":false,"loggedIn":true,"pageTitle":"视频号助手",
 "href":"https://channels.weixin.qq.com/platform/post/create","items":[],
 "message":"没读到评论：可能这个账号还没有评论，或页面结构变了…"}
```

关键线索是 `href` 还停在 `/platform/post/create`（发表动态页），说明**导航到评论页根本没成功**，
而 `comments()` 的 catch 只做了「回落到 homeUrl」，homeUrl 对视频号就是发表页，等于原地打转。

## 2. 根因
视频号发表动态页上留着上次发布测试填过的表单（脏状态），Chromium 在离开该页时会触发
`beforeunload` 确认；隐藏窗口下没有人点「离开」，于是每次导航都被 `net::ERR_ABORTED` 拦下、URL 不变。
`navigate()` 在 0.1.21 已经把这种情况识别为失败，但上层（comments/stats/replyComment）只会回落到首页，
不会换一个干净窗口重来。

## 3. 修复（packages/desktop/src/main/platform.ts）
新增 `private async navigateResilient(platform, win, url)`：

1. 先 `navigate()`，成功就直接返回；
2. 失败时读当前 `href`，**已经停在目标页**（只是 DOM 超时）就直接返回，不重建；
3. 否则记日志 `[平台] 页面被未提交表单拦住，重建窗口后重试：…`，
   `destroyWindow` 销毁旧窗口 → `ensureWindow` 建干净窗口（登录态在持久分区 `persist:platform-<id>` 里，不受影响）→ 再 `navigate`。

调用点全部换成它：
- `comments()`：`win = await this.navigateResilient(id, win, driver.commentsUrl)`（失败回落 homeUrl 也用同一个函数）
- `stats()`：`win = await this.navigateResilient(id, win, driver.dataUrl)`
- `replyComment()` 的「打开评论管理」步骤

## 4. 真机验证（安装版 0.1.21 + 打补丁 build，2026-11-10T08:59Z）
`window.fcm.platform.comments({platform:'shipinhao', maxItems:20})`：

```json
{"ok":true,"loggedIn":true,"pageTitle":"视频号助手",
 "href":"https://channels.weixin.qq.com/platform/interaction/comment",
 "selector":".comment-item",
 "items":[{"index":0,"text":"向日葵先生141319：爱跑王子（2024/09/23 01:39）"}],
 "message":"已读取 视频号 评论 1 条（选择器 .comment-item）"}
```

href 变成 `/platform/interaction/comment`，说明硬重置绕开了 beforeunload。

备注：**没有再次给真实客户评论发测试回复**。回复链路（定位评论 → 点「回复」→ 填内容 → 发送）
在 0.1.18 的 P32 校准里已经在同一条评论上真机跑通过（见 `docs/handoff/P32-视频号评论.md`），
本次只改了导航方式，选择器与发送逻辑没动，故不再对真实用户重复发公开回复。
