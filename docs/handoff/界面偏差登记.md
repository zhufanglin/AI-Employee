## 已确认的偏差

### D-01 桌面端新增「文生图」「图生视频」两个一级入口（2026-11-06 发现）
- **原版事实**：服务端确有 `POST /api/media/images/generations`、`POST /api/media/video/generations`（`server1027/dist/media-proxy/media-proxy.controller.js:157,165`，转发到 media-agent 的 `/compute/media/images/generations`、`/compute/media/video/generations`），定价表也有 `image_gen 20/次`、`video_gen 20/次`；但**客户端没有对应页面**。
- **原版客户端文案证据**（`_extract/renderer_0429_strings.txt`）：
  - 第 9571-9575 行是一串任务步骤：`采集内容 → 渠道采集信息 → 生成文案 → 生成视频 → 发送评论`（即「生成视频」是团队任务链里的一步，不是独立页面）
  - 第 10166-10174 行：`IP口播视频` / `IP口播视频制作` / `未找到「IP口播视频制作」定时任务（traffic_ip_video_workflow）`
  - 第 44796 行 `真人口播混剪`；第 44815/44990/45218 行「视频上传成功，可直接用于数字人合成」
  - 第 38897 行 `每日海报制作`、第 38059 行 `推送海报资讯`（海报走图片模型，是销售工具/团队任务的动作）
- **原版信息架构**：`工作台`（8574）、`08-内容中心`（16742）、`/content`（15374）、`/materials`（17469）、`获客`（9730）、`招募/团队` 等；**没有「文生图」「图生视频」这类创作 tab**。
- **我们的偏差**：`packages/desktop/src/renderer/src/pages/Shell.tsx` 新增了两个一级 nav（🖼️ 文生图 / 🎞️ 图生视频，39-40 行），页面 `MediaCreation.tsx`。原因是我们把「先能用」实现成了「把原子能力暴露成入口」。
- **影响**：①信息架构不忠实（F4/F3）；②把原版的后台能力做成了用户可点入口，顺带把「成本亏损」暴露出来（文生图 3 次上游 314 币只收 60 积分）。
- **决定（2026-11-06 用户选择 B）**：保留能力，但**折叠进「🧪 高级 / 实验」分组，默认收起**（`Shell.tsx` 的 `nav-group`，点箭头展开；当用户在该页时自动展开）。一级 nav 恢复为：对话 / 员工办公区 / 数字人 / 音色克隆 / 积分与用量 / 渠道网关 / 设置。截图：`_smoke_nav.png`。
- **原处置建议（历史）**：
  - **A（推荐，最忠实）**：撤掉两个一级 nav；把能力收进原版语义里 —— 海报生成进「内容中心/销售工具」、视频相关进「IP口播/混剪」流程，数字人页保留（对应原版「数字人合成」）、音色克隆页保留（对应「播报音色」，4888 行）。
  - B：保留但折叠进「高级/实验」区域，复刻收口时再决定。
  - C：保持原样（不推荐，属于功能扩张而非复刻）。

## D-02「渠道网关」页 —— 核对后判定：**不算偏差**
- 原版证据（`_extract/renderer_0429_strings.txt`）：16744「04-渠道中心」、9481「连接消息渠道」、9486「您的渠道已配置。将在网关启动时连接。」、9579「私信渠道」，另有 `/channels` 路由与 `channel:validate/setEnabled/whatsapp-qr` 等 IPC。
- 结论：原版确实有「渠道中心」页并直接提到"网关启动时连接"，我们的「渠道网关」页（渠道列表 + 网关启停/日志/控制台）语义一致，只是把「渠道配置」与「网关运维」合并到一页。**保留，不登记为偏差**。

## D-03「积分与用量」页 —— 核对后判定：**经批准偏差（因裁剪订阅）**
