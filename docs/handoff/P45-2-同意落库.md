> 日期：2026-11-12

## 一、为什么做

合规清单第二节列出的公司侧风险里，「数据出境单独同意」和「日志留存 6 个月」是**代码侧就能补的**两条硬要求：

1. 《个人信息保护法》第 38/39 条：个人信息出境需要**单独同意**，不能被「同意用户协议」一并推定。我们所有对话/任务数据都在阿里云美国弗吉尼亚处理，属于出境。
2. 《网络安全法》第 21 条：网络日志留存不少于 6 个月。原来 logrotate 只留 14 天。
3. 登录页缺少协议链接行（应用市场审核常见驳回点）。

## 二、实现

### 2.1 数据库：ConsentRecord

```prisma
model ConsentRecord {
  id        String   @id @default(cuid())
  userId    String
  docKey    String   @db.VarChar(32)   // terms | privacy | aigc | cross-border
  version   String   @db.VarChar(32)
  source    String   @db.VarChar(32)   // desktop | settings | smoke | prod-probe
  ip        String?  @db.VarChar(64)
  userAgent String?  @db.VarChar(255)
  createdAt DateTime @default(now())
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([userId, docKey, version])
  @@index([userId, createdAt])
  @@map("ConsentRecord")
}
```

迁移：`20261112091121_p45_consent_record`。

### 2.2 服务端 `packages/server/src/auth/`

| 位置 | 内容 |
| --- | --- |
| `auth.service.ts` | `ConsentInput` 类型；`CONSENT_DOCS = ["terms","privacy","aigc"]`；`assertConsentForNewAccount()`（env `AUTH_REQUIRE_CONSENT`，默认 `1`）；`recordConsent(userId, consent?, fallbackSource)` 逐文档 create，`P2002` 视为幂等；`crossBorder === true` 才追加 `"cross-border"` 记录 |
| `smsLogin()` | 新用户：先 `assertConsentForNewAccount` → 建号 → `recordConsent`；老用户：只补记（不会因为升级被拦） |
| `register()` / `passwordLogin()` | 注册强制；密码登录只补记 |
| `auth.dto.ts` | `ConsentDto { version?, crossBorder?, source? }`，三个 DTO 都加可选 `consent` |
| `auth.controller.ts` | `withClientMeta(consent, req)` 注入真实 IP（`x-forwarded-for` 首段）与 UA |

**顺手修的真 bug**：`issueToken()` 原载荷 `{sub,role,phone,kind}` 在同一用户同一秒两次登录会产出**完全相同**的 JWT，写 `Session.accessToken`（唯一键）直接 500。已加 `jti: randomBytes(8).toString("hex")`。

### 2.4 已登录用户「立即落库」

0.1.27 上线后发现一个合规缺口：同意记录只在**登录/注册**时上报，已登录用户在启动闸门或设置页重新同意时只写本机 settings.json，服务端没有记录——只要用户不重新登录，条款改版后的「重新同意」就查无实据。

补法（0.1.28 起）：

| 位置 | 内容 |
| --- | --- |
| packages/server/src/auth/auth.controller.ts | 新增 @ApiBearerAuth() @Post("consent") → async recordConsent()：recordConsent(user.id, withClientMeta(dto.consent, req), "desktop")，返回 { success: true, created } |
| packages/desktop/src/main/index.ts | legal:accept 改为 async：先落本机 settings，再 if (settings.token) await api('/auth/consent', { method: 'POST', body: JSON.stringify({ consent: consentPayload() }) })；失败只 console.error（离线也要能用），返回体加 recorded |
| packages/desktop/src/renderer/src/types.ts | legal.accept 返回类型加 recorded?: boolean |

幂等性由 @@unique([userId, docKey, version]) + P2002 忽略保证，所以重复点「同意并继续」不会堆记录。

## 四、运维注意

1. **老客户端（≤0.1.26）首次注册会被拦**：它们不发送 `consent` 载荷，服务端返回中文提示。这会推动用户升级；如需临时放行，把生产 `/opt/fcmediaagent/app/.env` 的 `AUTH_REQUIRE_CONSENT` 设为 `0` 并重启 api（不推荐，属于合规退让）。
2. 生产迁移命令：`cd /opt/fcmediaagent/app && export PATH=/opt/node/bin:$PATH && ./node_modules/.bin/prisma migrate deploy`（部署脚本 `_deploy/p45b-deploy.sh` 已封装）。
3. 本地 dev 库的 17 名员工 `skillMd` 若变旧，`smoke-t36` 会红：跑 `node scripts/_local-apply-skills.mjs` 刷新。
4. 冒烟脚本已统一补 `consent` 载荷（15 个脚本），以后新写登录冒烟记得带上，否则会 400。
5. **0.1.27 的已知缺口（0.1.28 已修）**：0.1.27 的用户在启动闸门点同意只写本机，服务端记录要等下次登录才补。0.1.28 起点同意即时上报。
