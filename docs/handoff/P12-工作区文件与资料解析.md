# P12 工作区文件与资料解析

> 日期：2026-11-07　范围：服务端能力层 + 工作区上传接口 + 桌面员工办公区附件　状态：已上线生产（0.1.3）

## 1. 为什么要做

P11 之后的复盘（`docs/handoff/P11-技能需求映射.md`）显示：17 个员工里 **12 个**卡在同一件事上——用户手里的客户名单、价格表、竞品资料进不来；员工只能凭空写，交付物自然不像样。
F2 缺口分级（`docs/handoff/F2-缺口分级与取舍.md`）把原版 `file:*` 8 个 IPC 列为 A 级第一簇，也对得上。

所以这一批补的是**数据入口**：用户上传资料 → 存进用户自己的工作区 → 员工在任务里按文件名读取（Excel/Word/PDF 解析成文本给模型）。

## 2. 能力清单（员工可用）

| 能力 | 参数 | 说明 |
| --- | --- | --- |
| `file_list` | `limit`（默认 20，上限 50） | 列出**当前用户**工作区文件，按更新时间倒序，返回 name/key/ext/bytes/updatedAt/url |
| `file_read` | `key` 或 `name`、`maxChars`（默认 8000，500–40000） | 读文本类文件（.md .txt .csv .json .html .xml .log），支持按文件名直接读 |
| `doc_read` | `key` 或 `name`、`maxChars`（同上） | 读 .xlsx/.xls（最多 5 个工作表，转 CSV 文本）、.docx（mammoth 抽正文）、.pdf（pdf-parse） |
| `file_write` | `name`、`content` | 写交付物，落到 `workspace/<userId>/<uuid>-<name>`，OSS 配置齐全时同时上传 |

三者都由 `packages/worker/tool-loop.mjs` 暴露给员工模型（能力白名单里新增 `file_list`/`doc_read`），17 个员工共享，差异只在 SKILL.md 怎么用它们。

## 3. 安全边界

- **用户隔离**：所有 key 必须是 `workspace/<自己的 userId>/` 前缀，否则抛「无权访问该文件」；按 `name` 查找也只在本人目录里找。
- **上传白名单**：文本 7 种 + 文档 4 种 + 图片/音视频 9 种；`.exe` 之类一律拒绝。
- **大小**：单文件写入 2MB（`WORKSPACE_MAX_BYTES`），上传 20MB（`WORKSPACE_UPLOAD_MAX_BYTES`），解析前 >60MB 直接拒。
- **文件名**：拒绝 `..`、路径分隔符、控制字符，长度 ≤80，必须带白名单扩展名；落盘时加 uuid 前缀防重名覆盖。
- **不读系统文件**：路径只由 `WORKSPACE_DIR` + userId + uuid 拼出来，用户传什么名字都不会越出目录。

## 4. 接口（桌面端用）

| 方法与路径 | 说明 |
| --- | --- |
| `POST /api/workspace/upload` | body `{ name, base64 }`（也接受 `fileName`/`content`/`dataUrl`），返回 name/key/ext/bytes/url |
| `GET /api/workspace/files?limit=50` | 返回 `{ total, items[] }` |
| `POST /api/workspace/delete` | body `{ key }` 或 `{ name }` |

桌面端：主进程新增 IPC `workspace:pick`（系统文件选择框，多选，>20MB 直接报错）、`workspace:list`、`workspace:remove`；渲染层 `EmployeeOffice` 新增「添加资料」按钮 + 附件 chip + 「我的资料库」面板。
提交任务时会把附件清单拼进任务说明：

```
本次任务可用的上传资料：
- 客户线索.xlsx（.xlsx，12KB）

读取方式：先用 file_list 确认文件名；文本文件用 file_read（参数 name），Excel/Word/PDF 用 doc_read（参数 name）。不要凭空猜测文件内容。
```

这样即使用户不写「请读一下附件」，模型也知道该去读。

## 7. 边界与没做的事

- `doc_read` 只抽文本：Excel 拿不到公式/样式/图表，Word 丢格式，PDF 扫描件（图片型）读出来是空。
- 只解析**文本内容**，不做图片 OCR、不做音视频转写（要另接）。
- 员工仍然只能读到「文件」，看不到用户桌面上的原始路径。
- 媒体任务（数字人/文生图）不走工作区，仍走 `/media/files/upload`。
- 生产 `PUBLIC_BASE_URL` 为空 ⇒ `url` 返回 OSS 直链；本地无 OSS 时返回 `PUBLIC_BASE_URL + /uploads/<key>`，两者都缺则 url 为 null（文件仍在磁盘）。

## 10. 经验

- PowerShell 里 `Start-Process -Wait` 等 NSIS 静默安装会长时间挂住（安装器进程装完仍驻留）⇒ 改为轮询目标 exe 的 `VersionInfo.ProductVersion` 判定装好，不要用 `-Wait`。
- 桌面冒烟必须等 React 渲染完成再断言 DOM；CDP 连上 page target 不等于页面已渲染。
- 版本号这类「应该自动的东西」不要写死兜底值，写死之后没人会注意到它一直显示旧版本。
