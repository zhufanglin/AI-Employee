# P33 一键分发（立即发到多个平台）

> 背景：P31 让**定时**发布支持多平台（客户端本地队列），但「现在就发」还是单平台单选。
> 用户 m14357 说「把「定时发布」扩到多平台一键分发：按你的节奏来就行」——本次把即时发布也补上。

## 1. 交互变化

`packages/desktop/src/renderer/src/pages/PlatformPublish.tsx`「新建发布」卡片：

- 去掉原来的「平台」单选下拉，换成**多选胶囊**（抖音 / 小红书 / 视频号），默认只选抖音；
- 未登录的平台在胶囊里带「（未登录）」提示（登录态来自 P28 缓存，不会额外触发检查）；
- 「全选」按钮一键选三个；
- 按钮文案：选 1 个 → 「开始发布」；选多个 → 「一键分发到 N 个平台」；
- 发布中显示「发布中，请勿关闭客户端…（1/3）正在发布到 小红书…」。

## 2. 执行语义

`publish()` 里：

1. 校验正文、素材、至少一个平台（中文提示）；
2. 组装一次 `payload`（type/title/content/tags/mediaPaths），循环 `targets` 时只覆盖 `platform`；
3. **严格串行**逐平台调用 `window.fcm.platform.publish`（平台窗口是同一个池、runExclusive 串行，避免抢焦点）；
4. 每发完一个平台就 `setMultiResults([...acc])` 落一次，中途崩溃也能看到已完成的部分；
5. 单平台失败**不中断**后续平台，失败项落 `{platform, ok:false, message, steps:[], screenshots:[]}`；
6. 全部结束后：只选 1 个平台 → 沿用原「发布结果」区块（含步骤与截图）；多平台 → 「分发结果 · x/y 个平台成功」表格 + 顶部错误条「n/m 个平台没发成功：小红书、视频号」。

标题长度不用特殊处理：各平台 driver 的 `clampTitle` 会按 `TITLE_LIMITS = { douyin: 30, xiaohongshu: 20, shipinhao: 16 }` 自动截断。

## 3. 与 P31 的区别

| | P31 定时多平台 | P33 立即分发 |
| --- | --- | --- |
| 触发 | 本地队列到点（`publish-queue.json` + 30s tick） | 用户点按钮 |
| 状态 | `pending → running → done/failed`，可重试、可持久化 | 一次性，只在页面内存里 |
| 结果 | `job.results[]` 落到队列文件 | `multiResults` 只在本页展示 |
| 失败处理 | 部分成功记 done + 说明；不自动补发 | 不自动重试，用户可再点一次（会对已成功的平台重复发） |
