# P26 定时发布（客户端本地队列）

## 为什么放客户端

服务端的员工定时任务（`EmployeeCron`）只存「员工 + cron 表达式」，不存要发布的内容；
而发布本身必须跑在用户本机的浏览器会话里（平台按 IP / 设备 / UA 风控，美国机房 IP 会被拦）。
所以定时发布做成**客户端本地队列**：

- 队列文件：`<userData>/publish-queue.json`（Windows: `%APPDATA%\中科元晟 AI员工\publish-queue.json`）
- 到点由主进程每 30 秒 tick 一次，触发 `platform.publish(...)`（复用已扫码登录的持久化分区）
- 客户端关着的时候到点的任务，下次打开立刻补发，超过 10 分钟记 `late`（界面显示「迟到补发」）

| `packages/desktop/src/main/index.ts` | 实例化队列、注册 IPC、`startQueueTimer()`（启动 20 秒后首跑，之后 30 秒一轮） |

| `packages/desktop/src/renderer/src/types.ts` | `ScheduledPublishJob` / `ScheduledPublishInput`，与主进程结构逐字对齐 |

### 任务状态机

```
add() → pending ──tick 到点──> running ──成功──> done（记 url）
                                  └──失败──> failed（记 message，可 retry → pending）
```

- 进程在 `running` 时被杀：下次启动读盘时统一回落到 `pending`，避免永远卡住。
- 同一时刻只发一条（`this.running` 互斥），避免三个平台抢窗口和鼠标。
- `attempts` 累加，界面显示「第 N 次」。

### 校验规则（`add`）

| 字段 | 规则 |
| --- | --- |
| platform | 只能是 `douyin` / `xiaohongshu` / `shipinhao` |
| title | 必填 |
| mediaPaths | 至少 1 个（逗号分隔字符串或数组） |
| scheduledAt | `datetime-local`（2026-11-09T09:30）或 ISO；必须是将来的时间（允许 60 秒容差） |
| tags | 逗号 / 空格切分 |

失败一律抛中文错误，IPC 层收敛成 `{ ok:false, error }`。

## 已知限制

1. **必须客户端在运行**。关机/退出期间不会发布（到点后补发）。要真正 7×24，得把定时发布交给一台常开的机器（例如家里那台跑网桥的 Windows）。
2. 发布失败不会自动重试，需要用户点「重试」（避免在平台风控时刷接口）。
3. 一条任务只发一个平台；同内容发多平台请建多条。
4. 素材路径是用户本机绝对路径，换机器/删文件会导致发布失败（失败原因会显示在列表里）。
