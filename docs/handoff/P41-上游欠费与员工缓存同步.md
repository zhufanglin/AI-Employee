## 二、代码修复（已部署生产）
1. `packages/server/src/providers/providers.service.ts`
   - 新增 `private upstreamError(target, status, text)`：把上游原始错误翻译成中文——
     欠费 → 「模型服务账户余额不足或已逾期（ark），请联系管理员充值后再试」code `UPSTREAM_ACCOUNT_OVERDUE`；
     模型不存在 → `UPSTREAM_MODEL_NOT_FOUND`；401/鉴权 → `UPSTREAM_AUTH_FAILED`；429/限流 → `UPSTREAM_RATE_LIMITED`；其余 `UPSTREAM_ERROR`。
   - `chat()` 与 `streamChat()` 都改走该函数（原来只吐「上游模型调用失败: 403 {...}」英文原文）。
2. `packages/server/src/capabilities/capability.service.ts`
   - 新增 `private errorMessage(error)`：Nest 的 `HttpException` 带结构化 response 时，取 `response.error.message`；
     原来只看 `error.message`，导致能力层永远只报 "Bad Gateway Exception"，真实原因被吞。
   - 生产实测（`/capabilities/run llm_text`）现在返回中文欠费说明。
3. `packages/worker/cloud-executor.mjs` 与 `packages/desktop/src/main/executor.ts`
   - 员工缓存（`employees` Map，60s TTL）命中不到 `task.employeeId` 时，**强制 `employeesAt = 0` 重新拉一次** `/employees/mine` 再判失败。
   - 真 bug 证据：审计第 5 轮最后 3 个员工（wechat-publisher / xhs-lead-agent / ai-team-orchestrator）刚被审计脚本装上、缓存还没过期，
     worker 直接抛「员工未安装或不在我的员工列表中，无法执行」（`worker.log` 12:04:30/12:04:41/12:04:51）。真实用户「刚装完就派活」同样会踩。
4. 生产员工目录同步（seed 只写新库，老库不会自动更新）
   - 新增 `scripts/export-employees.mjs`（本地把 `packages/server/prisma/employees.ts` 导出 `_deploy/employees.json`，Node 24 直接跑 .ts）
     与 `scripts/prod-sync-employees.mjs`（生产 upsert 17 个员工，`skillMd` 取 `_deploy/skills-md.json`）。
   - 生产执行结果：`SYNCED 17 REQUIRED_LEFT 0`（此前 DB 里 boss-video-auto-editor / boss-wechat-publisher 仍是 `cliRequirement=required`，
     即 P39 的改动只改了种子文件、没进老库）。
