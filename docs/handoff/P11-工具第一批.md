# P11 工具第一批：联网搜索 + 工作区文件读写

> 2026-11-07 ｜ dsh-lead ｜ 对应 `docs/handoff/P11-执行prompt.md` 第 1–4 部分

## 1. 为什么做

复刻到 2026-11-07 时，17 个员工的工具白名单是固定的 7 个业务能力 + 2 个媒体能力（`packages/worker/tool-loop.mjs:2`）：
`web_extract`、`content_save`、`content_query`、`distribution_save`、`customer_save`、`customer_query`、`llm_text` + `image_gen`、`video_gen`。

缺的是「员工真正干活时最常用的两件事」：
- **找信息**：只能抓已知 URL，无法检索 —— 员工做选题、找对标、查政策时只能靠模型记忆，容易编。
- **交文件**：长清单、表格、脚本只能塞在聊天正文里，用户要自己复制。

本批补 `web_search`、`file_write`、`file_read` 三个能力。**员工共享**同一套工具，不按员工分别配。

## 2. web_search（联网搜索）

落点：`packages/server/src/capabilities/capabilities/search.ts`，注册在 `capability.service.ts` 的 descriptors 与 handlers。

参数：
- `query` 必填，检索词，≤ 400 字
- `maxResults` 可选，1–10，默认 5
- `days` 可选，只取最近 N 天（1–365，仅 Tavily 生效）

返回：`{ provider, query, total, items: [{ title, url, snippet, published }] }`；单条 snippet 截 400 字，总预算 6000 字（防上下文爆炸）。

供应商（env）：
- `SEARCH_PROVIDER` = `tavily` | `bing`；留空自动探测（有 `TAVILY_API_KEY` 用 tavily，否则 bing）
- Tavily：`POST https://api.tavily.com/search`，body `{ api_key, query, max_results, search_depth: "basic", days }`，超时 20s
- Bing：`GET https://api.bing.microsoft.com/v7.0/search?q=&count=&mkt=zh-CN`，header `Ocp-Apim-Subscription-Key`

**关键设计**：一个 key 都没配时，能力**直接抛错**「未配置搜索服务，请联系管理员配置 TAVILY_API_KEY 或 BING_SEARCH_KEY」，绝不返回空数组 —— 空数组会让模型以为「搜了没结果」然后自由发挥。

不计积分（与原版 tavily-search 预装技能一致，只消耗模型 token）。

## 3. file_write / file_read（工作区文件）

落点：`packages/server/src/capabilities/capabilities/files.ts`。

### 3.1 file_write
- `name` 必填，含扩展名；`content` 必填；`mime` 可选（默认按扩展名推断）
- 返回 `{ name, bytes, url, key }`

### 3.2 file_read
- `key` 必填（file_write 返回的 key）；`maxChars` 可选，默认 8000，下限 500，上限 40000
- 返回 `{ name, bytes, truncated, text }`

### 3.3 存储与安全
- 对象键：`workspace/<userId>/<uuid>-<safeName>`；本地目录 `WORKSPACE_DIR`（默认 `./uploads/workspace`）
- OSS 四件套（`OSS_ACCESS_KEY_ID/SECRET/BUCKET/REGION/ENDPOINT`）齐全时**同时**上传，返回 OSS 公网 url；否则 url 由 `PUBLIC_BASE_URL + /uploads/<key>` 拼；两者都没有则 `url = null`，只给 key
- 文件名白名单字符：中文/字母/数字/下划线/点/短横，长度 ≤ 80；拒绝 `..`、斜杠、控制字符
- 扩展名白名单：`.md .txt .csv .json .html .xml .log`（可执行类型一律拒）
- 单文件 ≤ `WORKSPACE_MAX_BYTES`（默认 2,000,000 字节）
- **越权防护**：`file_read` 的 key 必须以 `workspace/<当前 userId>/` 开头，否则抛「无权访问该文件」；读不到本地文件时才回落到 OSS 取

不计积分。

## 4. 工具循环接入

`packages/worker/tool-loop.mjs`：
- `CAPABILITIES` 集合加入 `web_search`、`file_write`、`file_read`
- `INSTRUCTIONS` 增加使用建议：搜索先用 `web_search` 拿标题与链接，再 `web_extract` 抓正文；交付清单/表格/长文用 `file_write` 落文件，并在 `finish` 正文给出文件名与下载链接

两个执行器（桌面 `packages/desktop/src/main/executor.ts`、云端 `packages/worker/cloud-executor.mjs`）**不需要改**：能力清单是运行时从 `GET /api/capabilities` 拉取、按 `CAPABILITIES` 过滤后拼进 system prompt 的（`tool-loop.mjs:72-74`），调用统一走 `POST /api/capabilities/run`（`:92-94`）。

## 6. 本批**没有**做的事（留给后续）

- `file_list`（列工作区目录）—— 很小，但本批先不开，避免员工乱翻
- `employee_dispatch`（员工之间派活）—— 涉及任务优先级/预算隔离，单独排
- `ffmpeg`（视频处理）—— 会给桌面安装包加约 70MB，等用户确认
- 搜索结果的**缓存去重**与**域名白名单**—— 先观察真实使用
- 未配置搜索 key 时**不降级**到模型记忆（宁可报错也不编）
