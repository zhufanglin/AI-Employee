# P30 平台取数结构化（文本快照 → 指标）

> 起因：P25 的 `packages/desktop/src/main/platform.ts` 的 `stats()` 只把抖音/小红书/视频号数据页的
> `document.body.innerText` 原样丢给模型（默认 4000 字，最多 12000 字），读起来费劲、数字口径不稳定。
> P30 在服务端补一层**纯函数**解析：文本进、结构化指标/作品出，不发网络请求、不读数据库、不碰 DOM。
> 桌面端接线由 Lead 负责（本轮不改 `packages/desktop/**`）。

## 一、文件与接口

新增：

- `packages/server/src/capabilities/platform-metrics.ts`
- 能力注册：`packages/server/src/capabilities/capability.service.ts`（3 处最小改动：import / descriptors / handlers）
- 单测：`scripts/smoke-p30-platform-metrics.mjs`（49 checks）
- 本文档

### 类型

```ts
export interface PlatformMetricItem {
  label: string;            // 归一后的中文指标名（播放量/点赞/...）；未知标签保留页面原文
  value: number | null;     // 万=1e4、亿=1e8、w/W=1e4、k/K=1e3；--/暂无 => null
  raw: string;              // 页面命中片段，例如 "12.3万"、"--"
}

export interface PlatformWork {
  title: string;
  playCount: number | null;
  likeCount: number | null;
  commentCount: number | null;
  publishedAt: string | null; // 页面原样（"2026-01-02"、"3天前"），不强行规范化
  raw: string;                // 整行原文
}

export interface PlatformMetrics {
  platform: string;           // 归一后的 id；平台非法时保留调用方原文
  ok: boolean;
  metrics: PlatformMetricItem[];
  works: PlatformWork[];
  notes: string[];            // 中文说明：非法参数/空文本/未解析到/百分比口径/补位提示
}

export function parsePlatformMetrics(platform: string, text: string): PlatformMetrics;
export function parseCnNumber(raw: string): number | null;
```

### 能力

- name：`platform_metrics_parse`
- category：`platform`
- params：`{ platform: string; text: string }`
- 返回：`PlatformMetrics`
- handler 与 parse 函数一样**不 throw**：参数非法只返回 `ok:false` + `notes`，由调用方决定怎么展示。
- **刻意没有**加进 `packages/worker/tool-loop.mjs` 的 CAPABILITIES：这是桌面/运维侧的解析工具，不给云端员工自主调用。

## 二、解析规则（只看文本，不依赖选择器）

1. **按行**：`text` 先按 `\r?\n` 切行，最多 5000 行（超出截断并写 notes）。
2. **挖噪音**：每行先把日期/相对时间（`2026-01-02`、`2026年1月2日`、`3天前`、`昨天` 等）和
   时间范围/分区标题（`近7天`、`数据概览`、`昨日`…）用空格替换；括号里的单位（`收益(元)`）同样挖掉。
   日期片段同时记为该作品的 `publishedAt`。
3. **认「标签 + 数字」**：
   - 横向：`播放量 12.3万`、`粉丝：1,234`、`12.3W 点赞`、`12.3万次播放`；
   - 竖向：上一行是标签、下一非空行只有一个数字（或 `--`/`暂无`）；
   - 空值横向：`播放量 --`、`收藏：暂无`、`收益(元) --` → `value:null`。
   - 标签左右两侧都可，匹配时按别名长度倒序，`视频播放量` 优先于 `播放`。
4. **指标词典**（15 组，中文 + 英文别名）：
   播放量 / 点赞 / 评论 / 分享 / 收藏 / 粉丝 / 关注 / 作品数 / 曝光量 / 完播率 / 互动率 / 点击率 /
   主页访问 / 收益 / 新增粉丝。英文认 `play`、`plays`、`views`、`likes`、`comments`、`shares`、
   `favorites`、`fans`、`followers`、`impressions`、`revenue` 等单词。
5. **数字**：`parseCnNumber` 支持 `1.2万`、`3.4w`、`12.3W`、`2亿`、`1,234`、`1.5k`、`10万+`、
   `45.2%`、`￥1,234.5`、全角数字；`--`/`—`/`暂无`/`暂无数据`/`无数据`/空串 → `null`；
   绝对值超过 **1e12** 截到 1e12。
6. **作品行**：一行里既有标题样式残留文本（≥2 字、非指标名/分区名），又有数字。
   - 带标签的数字按 播放/点赞/评论 映射；
   - 无标签数字按「播放、点赞、评论」顺序补位，并在 `notes` 里提示可能错位；
   - 标题里的日期/数字会被挖掉，`raw` 保留整行；
   - 完全相同的作品行（标题+三个计数）只保留第一次。
7. **去重**：同一指标 key（未知标签按归一 label）只保留第一次出现的值；后出现的 `近7天播放量`
   不会覆盖前面的总播放量。
8. **ok:false 分支**（不 throw）：
   - `platform` 不是 douyin/xiaohongshu/shipinhao（含中文别名 `抖音`/`小红书`/`视频号`）→ 中文 notes；
   - `text` 为空/全空白 → 中文 notes；
   - 合法输入但一个指标/作品都没解析到 → notes + 若文本含「请先登录/扫码登录」再补一条未登录提示。

## 三、已知限制（重要，接线前先看）

- **页面改版会漏字段**：词典是有限集合，平台新增/改名指标（如「主页访问率」换成「主页访问量」）
  会落到未知标签或直接漏掉。未知标签会原样保留，但不会归一到已知 key。
- **只解析首屏/截断后的文本**：桌面端 `stats()` 默认只取 4000 字（最多 12000 字），下面滚动的作品
  列表、分页数据都看不到；`maxChars` 调大才能多解析。
- **不猜百分比基数**：`45.2%` 只记 `45.2`，不换算成 0.452，也不去猜「完播率的分母是谁」；
  同理不把「较上周 +2.1%」当作品/指标。
- **无标签数字靠位置猜**：作品行没有字段标签时按「播放、点赞、评论」顺序补位，字段顺序变了就会错位
  （notes 会提示）。有标签时不受影响。
- **标题与数据分行的卡片排版**：目前只认「标题 + 数字在同一行」的作品；如果页面是「标题一行、
  播放/点赞/评论各一行」，数字行会被当成账号指标，标题行不会生成作品。要支持需再做「标题行 + 后续
  统计行」的聚合，容易和账号总览混淆，本轮不做。
- **相对时间原样保留**：`3天前`/`昨天` 不做日期换算（没有基准时间，猜了更糟）。
- **未登录页**：只能根据 `请先登录`/`扫码登录` 等文字给提示，不能确认登录态（登录态在桌面端判定）。
- **不落库、不缓存**：每次调用都是纯函数重算；同页面的历史对比不在这里做。

## 五、接线建议（Lead）

1. 服务端 `/capabilities` 已能看到 `platform_metrics_parse`，直接 `runStrict(user, "platform_metrics_parse", { platform, text })` 即可。
2. 桌面端 `platform_stats` 拿回快照后，既可以原样给模型，也可以把 `snapshot.text` 先送服务端解析一次，
   只把 `metrics/works/notes` 给模型（省 token、口径稳定）。**本轮没有改 desktop，避免和 Lead 的接线冲突。**
3. 真机验收时优先看 `notes`：出现「未从文本中解析到」多半是页面没加载完/未登录；出现「顺序填充」
   说明该平台作品行没有字段标签，需要按真机页面补词典或补分行聚合逻辑。
