# OSS 连接诊断（2026-11-06）

- 本地 OSS 配置项均存在，已有对象 HEAD 返回 200；35 字节、512 字节和 2 KB 测试对象完成写入、读取、校验和删除。
- 本地 SDK 普通 PUT 测试中，8 KB（两次）、256 KB 与 3,393,550 字节图片出现连接错误；1 KB 分块流式传输 8 KB 成功，但 256 KB 流式传输超时，不能作为可靠修复。curl 使用短期签名 URL 上传同一图片也超时，测试未输出签名或凭据。
- 某次 OPTIONS 请求本机连接超时，重试时上传 262,144 字节并收到 400；该 400 是无权限测试请求的服务端响应，并非上传成功。说明本机网络具有间歇性，不能仅凭单次成功认定稳定。
- 隔离机只读 GET 同一已有 OSS 文件返回 200、2,219,145 字节；隔离机无 OSS 凭据，没有复制本机密钥过去。隔离机的无权限 OPTIONS 测试收到预期 400，不能作为正式上传通过的证据。
- 本机 DNS 使用 VPN fake-IP；HTTPS 解析探测出现过成功、连接超时和 TLS 重置。以上只能支持“本机到云服务的网络链路不稳定”的判断，尚不能确定 VPN、链路、OSS 或 SDK 中哪一项是根因。
- 在当前已登录阿里云控制台的主账号中，OSS 控制台显示“尚未开通”；同时项目配置的密钥可访问已有桶。桶的归属与当前登录账号之间的关系尚未核实，不应仅凭此推断密钥失效或开通新服务。
- 用户提供的表格中，有一组凭据与本地项目配置一致，对应当前主账号下 RAM 用户 `Stu`；其自定义策略明确引用 `zhongke001`。查询桶信息和对象列表仍得到 403，尚不能确认桶所有者或拒绝原因。
- 只读查看 RAM 控制台发现 `Stu` 还被授予 OSS、ECS、RDS、RAM 等账号级较宽权限。项目内 OSS 应用代码目前仅调用对象上传；尚未验证该 RAM 用户是否被其他应用使用，因此不得直接撤销现有权限或密钥。建议先审计依赖、准备专用最小权限账号和轮换计划，再由用户确认变更。
- 诊断对象均在 `media/diagnostics/codex-...`，已知成功对象均已删除；已知异常对象在核查时 HEAD 显示不存在，超时请求的延迟结果仍无法完全排除。第一次 3.4 MB 测试的对象名未被记录，写入返回不确定；当前凭据没有对象列表权限，无法排除该次有遗留对象，需通过拥有列表权限的管理员按时间及前缀核查，不能扩大现有密钥权限或猜测删除。
- 未改动生产服务器、OSS 权限、VPN、服务端 `.env` 或现有密钥。
