# P42：战略表 + 人设表（忠实复刻原版注入方式）

## 一、依据
`docs/handoff/P42-原版战略表人设表-逆向.md`（445 行，子代理逆向，逐条带路径+行号+原文）。核心结论：
1. 「战略表」不是一张表，而是**飞书在线文档正文（10 节长文）** + 独立的「战略迭代记录表」只存版本历史。
2. 「人设表」= 人设规划表，8 字段（日期/名称/人设规划/定位/创建时间/所属账号/粉丝量/主页链接），一账号一行。
3. 注入方式 = **运行时拉取 + 截断 6000 字，拼进当次 LLM 的 user prompt**，不是常驻 system prompt；三档兜底 飞书 API → Playwright → SOUL.md 摘要，TTL 300s。
4. 关系是「岗位技能 + 数据叠加」，不是「读战略自己拆活」；每份 SOUL 自带「输入源表」，按员工声明注入。
5. 客户端没有战略/人设表单，也没有「训练/喂养/语料」（渲染层这三个词命中 0）。

## 二、实现（四步）
### 1) 存储与通道
- 战略正文 = 工作区文件 `<workspace>/<userId>/企业战略.md`（带 front-matter `version/updated/owner`）。**必须落在 capability 层 `userDir(userId)`**，否则员工的 `file_list/file_read` 看不到（`packages/server/src/capabilities/capabilities/files.ts:147`）。
- Prisma 首版只加 2 张表（另有 `PersonaProfile`，合计 3 个 model，迁移 `20261110145757_p42_strategy_persona`）：
  `StrategyDoc`(phone @unique / version / filePath / updatedBy / updatedAt)、`StrategyIteration`(versionNo / versionType / iteratedAt / trigger / sections / summary / author / docUrl)、`PersonaProfile`(name / positioning / plan / accountId / followers / homepage / effectiveAt / @@index([phone,name]))。
- `packages/server/src/strategy/`：`strategy.service.ts`、`strategy.controller.ts`、`persona.controller.ts`、`strategy.module.ts`。
- REST：`GET /api/strategy`（首次自动播种 10 节模板 + 建行）、`PUT /api/strategy`（V1.0→V1.1，写文件 + 追加迭代）、`GET /api/strategy/iterations`（最近 20）、`GET|POST /api/personas`（**POST 要 @HttpCode(200)**，按 (phone,name) upsert）、`DELETE /api/personas/:id`（越权 404）。

### 2) 注入链（worker）
`packages/worker/tool-loop.mjs`：`STRATEGY_BUDGET = 6000`、`PERSONA_BUDGET = 1500`，新增三个导出：
- `needsSection(needs)` → `## 当前员工岗位的数据授权`
- `strategySection(strategy, meta)` → `## 公司战略（当前版本 Vx.y），更新于 YYYY-MM-DD` + 「与它冲突的说法以它为准，它没写到的事实不要编造」+ 超长 `[战略文档已截断]`
- `personaSection(persona)` → `## 账号人设` + 「这是账号人设，不是客服话术」+ `[人设资料已截断]`
注入顺序（越靠后权重越高）：`INSTRUCTIONS` → 能力参数说明 → needs → SKILL.md → 战略 → 人设。
`runToolLoop({ api, model, messages, skill, strategy, persona, needs, strategyMeta, maxSteps, timeoutMs, pollMs, signal })`。
单测 `packages/worker/tool-loop-parse.test.mjs` 16/16 pass（新增 7 个 P42 用例）。

### 3) 按岗位授权（SKILL.md needs）
17 份 SKILL.md front-matter 增加一行，格式 `needs: [strategy.sections:产品体系, 竞争与优势, 服务客户人群, persona]`。
含 `persona` 的 7 个岗位（内容/流量类）：boss-blogger-deconstructor、boss-comment-opportunity、boss-competitor-viral-radar、boss-daily-lead-topics、boss-video-lead-script、boss-wechat-publisher、boss-xhs-lead-agent。销售/客服类只读战略，避免污染话术。

### 4) 下发与执行器接线
- `packages/server/src/employee/employee.service.ts`（pullTasks）与 `employee-execution.service.ts`（claimCloudTasks）：按 `userId → User.phone` 取 owner，`parseNeeds(skillMd)` 拆 needs，`resolveForEmployee(userId, phone, needs)` 按节切片，随任务下发 `employeeNeeds / strategyText / personaText / strategyVersion / strategyUpdatedAt`。
- `packages/worker/cloud-executor.mjs`：`api: toolCall`，日志 `[worker] model = … skillChars = … strategyChars = … personaChars = … needs = N`（看 strategyChars 判断注入是否生效）。
- `packages/desktop/src/main/executor.ts`：同样接线（桌面执行器）。

## 三、桌面端
- `packages/desktop/src/main/strategy-ops.ts`：`registerStrategyOps(ipc, { api })`，统一 `{ok:true,data}|{ok:false,error}`，路径**不能带 /api 前缀**（`api()` 的 base 已含 `/api`，否则 `Cannot GET /api/api/strategy`）。
- IPC：`strategy:get|save|iterations`、`persona:list|save|remove`；preload 暴露 `window.fcm.strategy.{get,save,iterations,listPersonas,savePersona,removePersona}`。
- `renderer/src/pages/Strategy.tsx`：两 tab「公司战略 / 账号人设」；战略页有版本行、「插入板块」下拉（10 节）、保存提示「已保存为 Vx.y」、折叠的迭代记录；人设页可编辑表格 + 新增/删除。
- `Shell.tsx` 侧栏加「🧭 战略与人设」。

## 四、验证
- `scripts/smoke-p42-strategy.mjs`（已加入 `scripts/verify.ps1`）：静态 43 项 + 在线 10 项，**53 checks ALL PASS**；在线部分验证 GET 模板 10 节、PUT 版本递增 V1.0→V1.1、迭代记录、**`GET /workspace/files` 能看到 `企业战略.md`**、人设增删。
- 本机真实客户端（patch-asar + CDP）对生产后端：`strategy:get` 返回模板，保存 V1.1 → 还原 V1.2，迭代 2 条，人设 save/list/remove 正常。
- 生产员工任务实证（boss-daily-lead-topics，云端执行器）：worker 日志 `skillChars = 1870 strategyChars = 0 personaChars = 126 needs = 5`，模型回答「本账号人设是工业除尘设备顾问，内容定位为专业、讲数据…」。
  **strategyChars = 0 的原因**：该验收账号当天没有打开过「战略与人设」页（战略文件在被读取时才播种），而人设表是接口写入的所以有值 ⇒ 说明按需读写、互不牵连。补种战略文件后同一账号再跑任务，战略正文即进入上下文。

## 五、已知取舍
- 不做「员工训练 / 喂养 / 语料」界面（原版也没有）。
- 人设只给 7 个内容/流量类岗位；销售类只读战略。
- 前端未强制 6000 字上限（服务端切片）；保存固定 `versionType=微调`、`trigger=手动编辑`；人设按 name upsert，改名会新增记录。
- `parseNeeds` 会把 `persona` 也放进 sections 列表（无匹配标题，无害）。
