# P31 定时发布：一条任务多平台分发

## 目标

P26 的定时发布是「一条任务只发一个平台」，同一份内容发抖音 / 小红书 / 视频号要建三条任务，容易漏发、时间也对不齐。
P31 把一条任务扩成**一键分发多平台**：用户在新建表单里勾选 1~3 个平台，到点后客户端**逐个平台串行**发布。

- 不改服务端、不改 IPC 通道协议（`queue:add` 原样透传入参）。
- 不引入新依赖，队列仍落在客户端 `<userData>/publish-queue.json`。
- 旧队列文件（只有 `platform`）与旧调用方（只传 `platform`）继续可用。

## 数据结构

```ts
interface PublishResult {
  platform: string   // douyin / xiaohongshu / shipinhao
  ok: boolean
  url?: string       // 成功时的作品链接
  message: string    // 成功提示或中文失败原因
}

interface ScheduledJob {
  id: string
  platform: string       // 兼容老队列/老 UI，恒等于 platforms[0]
  platforms: string[]    // 去重后 1~3 个，按用户勾选顺序
  results: PublishResult[] // 每发完一个平台落一条
  // ...P26 原有字段（type/title/content/tags/mediaPaths/scheduledAt/status/attempts/...）
}
```

读盘时统一归一：

- 有 `platforms` 用它，没有则回退到 `platform`；
- 非法平台项丢弃，去重后最多保留 3 个，一个都不剩则整条任务丢弃；
- 缺失/损坏的 `results` 补成空数组。

## 状态机（含 partial 语义）

```
add() → pending ──tick 到点──> running
                                 │
                                 ├─ 逐个平台 publish()，每完成一个 push result + save()
                                 │
                                 ├─ 全部成功 ─────────> done    message = "3 个平台全部发布成功"
                                 ├─ 部分成功 ─────────> done    message = "2/3 个平台发布成功，失败：小红书（原因）"
                                 └─ 全部失败 ─────────> failed  message = "全部平台发布失败：抖音（原因）、小红书（原因）、视频号（原因）"
                                                              └─ retry() → pending（清空 results，所有平台重发一遍）
```

关键语义：

| 结果 | status | 是否自动重试 | url |
| --- | --- | --- | --- |
| 全部成功 | `done` | 否 | 第一个成功平台的链接 |
| 部分成功（1~2 个失败） | `done` | **否**（否则会把已成功的平台再发一遍） | 第一个成功平台的链接 |
| 全部失败 | `failed` | 否（需手动点「重试」） | 不写 |

补充：

- 某个平台抛异常只记该平台失败，**继续发后面的平台**。
- 每发完一个平台立即 `save()`，进程中途崩溃后盘上仍能看到已完成哪几个平台。
- 重启时 `running` 统一回落 `pending`；重跑会清空旧 results 并重发所有平台。
- 单平台任务保留 P26 原文案（成功用 publish 返回的 message，失败原样展示原因），避免老界面/老用例回归。
- `attempts` 仍在每次执行时 +1，界面显示「第 N 次」；达到 3 次仍失败会追加「（已尝试 3 次，可手动重试）」。

## 校验规则（`add`）

| 字段 | 规则 | 失败文案 |
| --- | --- | --- |
| `platforms` | 必须是数组 | 平台参数格式不对：platforms 必须是平台 id 数组 |
| `platforms` 数量 | 1~3 个（去重前先卡最多 3） | 最多选择 3 个发布平台 / 至少选择一个发布平台 |
| `platforms` 取值 | 必须在 `douyin / xiaohongshu / shipinhao` 白名单 | 平台只能是 douyin / xiaohongshu / shipinhao（收到：…） |
| 兼容 `platform` | 未传 `platforms` 时按单平台处理，内部归一成 `[platform]` | 同上 |
| 去重 | 重复平台按首次出现顺序去重 | — |
| 其他字段 | 与 P26 一致（标题/素材/时间） | 中文文案不变 |

同时传 `platform` 与 `platforms` 时以 `platforms` 为准。

## 执行顺序与失败隔离

```ts
for (const platform of job.platforms) {   // 串行，不并发
  try {
    const result = await publish({ platform, ... })   // 单平台，复用 platform.publish
    job.results.push(...)
  } catch (e) {
    job.results.push({ platform, ok: false, message: ... }) // 只影响当前平台
  }
  this.save()   // 每个平台一落盘
}
```

平台窗口、鼠标、剪贴板都是独占资源，所以**不能并发**；串行也保证平台风控看到的是稳定节奏。

## 界面

`packages/desktop/src/renderer/src/pages/Scheduled.tsx`：

- 新建表单「平台」由单选 `<select>` 改为三个 checkbox + 「全选 / 取消全选」；默认勾选抖音。
- 不勾任何平台时提交按钮禁用，并提示「请至少勾选一个平台」。
- 队列表格「平台」列显示 `抖音/小红书` 这种拼接。
- 「结果」列每个平台一行：`✓ 抖音 已发布` / `✗ 小红书 原因`，成功且有链接时「已发布」可点开作品。
- 订阅 `queue:event`：每完成一个平台主进程推 `action: 'progress'`，页面实时刷新进度。

## 已知限制

1. **串行导致耗时变长**：勾 3 个平台的总耗时约等于 3 次单平台发布之和（含每次打开/关闭平台窗口），不适合卡点秒发。
2. **一个平台失败不影响其它平台**：但「部分成功」会直接标 `done`，不会自动补发失败平台；需要补发只能新建一条只勾失败平台的任务（或全失败后点重试）。
3. **重试会重发所有平台**：`retry()` 清空 `results` 后按 `platforms` 全量重跑，**已经成功过的平台也会再发一遍**，可能造成重复作品；点重试前请确认。
4. 客户端必须开着；关机/退出期间到点的任务下次启动补发，超过 10 分钟标「迟到补发」。
5. 素材是本机绝对路径，换机器/删文件会让对应平台发布失败；失败原因会显示在该平台那一行。
6. 一条任务上限 3 个平台（与平台白名单数量一致），当前不支持自定义平台。
