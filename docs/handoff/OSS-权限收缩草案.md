# OSS 权限收缩草案（仅供核对）

## 已核实

- 用户提供的表格中，RAM 用户 `Stu` 的一组密钥与本机项目 OSS 配置一致；文档不记录密钥或完整账号标识。
- 当前 RAM 控制台显示，该用户除 OSS 权限外，还有账号级 ECS、RDS、RAM 等管理权限及 PowerUserAccess。其自定义策略引用 `zhongke001`，但存储桶归属尚未由桶信息接口确认。
- 检索当前 `packages/server/src` 与 `packages/worker`，应用使用 OSS 凭据的位置在媒体服务，当前代码调用对象上传；诊断脚本还调用 HEAD、GET、DELETE、LIST，不代表线上应用都需要这些权限。
- 不能断定 `Stu` 只供本项目使用，也不能依据本地搜索断定没有其他机器、应用或人员依赖它。

## 待实施方案

1. 先确认 `zhongke001` 的所有者、跨账号授权关系、当前线上依赖与应用所需的对象前缀。
2. 准备独立、仅供项目上传的身份；以 `oss:PutObject` 和实际需要的桶及前缀为候选最小权限，其他权限按隔离环境验证结果再决定。读取、列举、删除或分片权限不能默认添加。
3. 在隔离环境使用新身份进行上传、读取及失败恢复验证，核对客户端访问路径；不把密钥写入仓库或对话。
4. 确认迁移方案及回滚方式后，再由获授权人员安排生产切换；最后评估轮换或回收旧密钥、缩减旧用户权限，避免影响其他依赖。

本文件是审查草案，不授予执行创建用户、变更授权、停用密钥或生产部署的权限。
