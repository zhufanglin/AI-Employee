# P39：17 个员工技能改造为真实能力编排

## 一、问题（改造前实测）
- 17 份 `packages/desktop/resources/skills/<slug>/SKILL.md` 里**没有一个提到真实存在的工具名**；其中 3 份还要求员工执行环境里根本不存在的 CLI：
  - `boss-video-auto-editor`：`python scripts/video_cli.py check / probe / render-segments`（依赖 FFmpeg/Whisper/auto-editor）
  - `boss-wechat-publisher`：`python scripts/wechat_cli.py check`
  - `boss-xhs-lead-agent`：`xhs-cli`
- `packages/server/prisma/employees.ts` 里 `cliRequirement: "required"` 只有前两个员工，导致它们被强制路由到桌面执行器，云端/微信渠道根本跑不了。
- 8 份 SKILL 提到「企业基础资料/客户资料」，但没有任何能力把公司资料注入上下文 ⇒ 模型只能编。

## 二、改造成什么（规范文档）
`docs/handoff/P39-员工技能改造规范.md`（6599B）规定硬约束：
- 只能引用 worker `CAPABILITIES` 白名单里的真实能力名；禁止 CLI / CRM / 飞书 / 假称已发布。
- 保留 front-matter `name`/`description`；保留原业务语义；≤7500B；全中文。
- 强制两节：`## 工具编排`（4–8 步，逐步写清工具名+参数）、`## 交付前自检`（四条）。

## 三、17 份重写结果（全部含两节、无违规词、3075–5151B）
获客类 5：boss-lead-radar 4768B、boss-export-sales-agent 4271B、boss-industry-researcher 4386B、boss-investment-researcher 4662B、boss-competitor-viral-radar 4311B。
销售类 4：boss-chat-deal-analyzer 4646B、boss-private-lead-manager 5016B、boss-sales-followup 4766B、boss-ai-team-orchestrator 5034B。
内容类 5：boss-blogger-deconstructor 4588B、boss-daily-lead-topics 4190B、boss-video-lead-script 4183B、boss-comment-opportunity 4769B、boss-geo-auditor 4784B。
我亲写的 3 份特殊岗位：
- `boss-video-auto-editor` 3413B：`media_info` 探测 + `media_process`（trim/concat/thumbnail/compress/transcode，trim 上限 600s、输入≤200MB 输出≤120MB）+ `file_write` 点位表 csv + `doc_write` 片单 xlsx；**明写「没有 ASR，不能假装听过内容」**，字幕需用户给文稿。
- `boss-xhs-lead-agent` 3415B：`web_search/web_extract/web_batch` 研究 + `file_write` 方案 + `image_gen` 出图 + `platform_status/platform_publish`（仅本机）+ `customer_save`。
- `boss-wechat-publisher` 2992B：**明写「当前版本没有公众号接口发布通道」**，产出 md + 可粘贴 HTML + docx + `distribution_save`，发布由用户手动粘贴。

## 四、配套改动
- `packages/server/prisma/employees.ts`：两个员工 `cliRequirement` → `"none"`（现在 0 个 required）；视频剪辑师 title/tools 改为读素材出片单，公众号发布官去掉「授权后可创建草稿并发布」。
- `packages/worker/tool-loop.mjs` `INSTRUCTIONS` 1583→1826 字符：开头加「开工前先 file_list 找《企业基础资料.md》《客户资料》，memory_search 查偏好，别凭空编公司信息」；结尾加交付纪律「只有真调用过工具才能说已生成/已发布/已导出/已剪辑；表格里的公司名、数字、链接必须来自搜索或抓取，没来源标『未核实』」。
- `packages/server/src/capabilities/capabilities/files.ts`：新增 `PROFILE_FILE = "企业基础资料.md"` + `PROFILE_TEMPLATE`（六节：企业与产品 / 目标客户 / 竞争与优势 / 获客与内容（含「老板 / 主理人人设」）/ 销售与私域 / 输出偏好）+ `export async function ensureWorkspaceSeed(userId)`（工作区目录不存在才写，用户删了不再塞回）；`listWorkspaceFiles()` 开头调用；`file_write` 写同名文件后删模板。
- `packages/desktop/src/renderer/src/pages/EmployeeOffice.tsx`：资料库文案改为说明模板会自动落地、上传同名文件即替换。

## 五、生产部署与审计（关键坑）
- 部署：`%TEMP%\p39x` → `tar -czf p39.tgz`（339 文件）→ scp → 远端解包 + `cp -a dist dist.bak.$TS` + `cp -r` + 覆盖 `worker/tool-loop.mjs` + `systemctl restart` ⇒ API=active WORKER=active HEALTH=200。
- 技能写库：`scripts/export-skills-md.mjs`（17 份 → JSON，**是 {slug: 全文} 对象不是数组**）→ `scripts/apply-skills-md.mjs`（createRequire('/opt/fcmediaagent/app/')）⇒ `APPLIED 17/17`、`EMPLOYEES_WITH_SKILLMD 17/17`。
- `skillChars` 是**字符数**不是字节（新技能约 2000–2100 字符 ≈ 4.5–4.8KB）；日志在 `/opt/fcmediaagent/logs/worker.log`（`[worker] model = … skillChars = N`），api.log 里没有。
- `FCM_EXECUTOR_MAX_STEPS` 只在 **systemd unit** `/etc/systemd/system/fcmediaagent-worker.service` 的 `Environment=` 行，改后 `daemon-reload` + restart；10 步时新技能编排会 FAILED「达到执行步数上限」，已调到 16。
- 审计脚本 `scripts/prod-audit-employees.mjs` 曾因 queued 超 120s 早退误判（云端 worker 单线程串行），已删早退，只由 `FCM_AUDIT_TIMEOUT_MS` 控制；支持 `FCM_AUDIT_ONLY` 过滤 slug。
- 清队列用 ASCII 前缀：`UPDATE EmployeeTask SET status='failed', error='P39 audit stale' WHERE title LIKE 'P39 %' AND status IN ('queued','running');`（中文 LIKE 在 docker mysql 连接字符集下静默 0 行）。

## 六、审计结论（第 5、6、7 轮）
17 个员工全部 `grade=OK`（status=awaiting_approval，都有 artifact）。样例：boss-geo-auditor 553s/5241 字/13 步、boss-export-sales-agent 5550 字/13 步、boss-ai-team-orchestrator 289s/3004 字、boss-video-auto-editor 36s/555 字（media_info 4.7s + media_process 18.7s，产出 `audit-clip-前3秒-trim.mp4`）。
途中修掉两个真实缺陷：
1. 云端 worker 员工目录 60s TTL 缓存不含刚安装的员工 ⇒ 「刚装上就派活必失败」；`cloud-executor.mjs` 与桌面 `executor.ts` 取不到 emp 时强制 `loadEmployees()` 重取一次。
2. worker 全局 180s 请求超时掐断长工具（llm_text 写长文）：新增 `FCM_TOOL_TIMEOUT_MS`（默认 600000），工具调用走 `toolCall()`，超时抛中文「调用超时（600 秒）…请缩小单次产出或分批重试」。
