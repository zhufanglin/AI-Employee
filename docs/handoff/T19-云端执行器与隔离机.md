# T-19 员工执行器（桌面本机 + 云端隔离机）

> 目标：让「AI 员工任务」真的有人执行，而不是只入队。
> 两条执行路径共用同一套服务端契约：`POST /employee-tasks/pull` 认领 → 执行 → `PATCH /employee-tasks/:id` 回写。

## 1. 架构

```
桌面端(Windows)  TaskExecutor(poll 8s) ─┐
                                       ├─> POST /employee-tasks/pull?limit=1  (用户令牌)
云端 worker(154.64.255.36)             ─┘        │
                                                ├─> POST /compute/chat/completions (同一用户令牌 → 代理 → 火山方舟)
                                                └─> PATCH /employee-tasks/:id  {status: awaiting_approval, outputText, artifacts}
```

- 任务由用户在桌面「办公区」点「运行」创建（`POST /employees/:slug/run`），字段 `executor` 决定归属：`desktop`（`employee-tasks/pull`）或 `cloud`（`employee-execution/pull`）。
- 服务端在 pull 前先跑 `recoverStalledTasks()`：`status=running` 且 `startedAt` 超过阈值（env `EMPLOYEE_TASK_STALL_MINUTES`，默认 10）→ 重新排队（最多 2 次），超次数置 `failed`。这保证执行节点崩溃/断电后任务不会永久挂起。

## 2. 桌面端执行器

代码：`packages/desktop/src/main/executor.ts`（class `TaskExecutor`）

- 轮询 8s（`FCM_EXECUTOR_POLL_MS`），首轮 1.5s；`status()` 暴露 `{running,busy,startedAt,lastRun,pollMs}`。
- 用员工档案（name/title/mission/coreDirective/description/capabilities/kpi/usageExample）拼 system prompt，user 为任务标题 + `input.text|prompt|JSON`。
- 产物：`<userData>/employee-output/<taskId>.md`（截断 200000 字符），并写 `outputMeta={executor:"desktop",model,usage}` + 两个 artifact（text + file）。
- IPC：`employee-execution:status|tick|start|stop`；渲染层「办公区」页头显示「本机执行器：执行中/待命中/已停止」。
- 冒烟：`FCM_SMOKE_EXECUTOR=1 FCM_SMOKE_MS=210000`（见 `packages/desktop/src/main/index.ts:142` 与 `:161`）。

### 部署流程（可重放）

1. 打包：`packages/server` 下 `tar -czf _staging_server.tar.gz dist prisma package.json` → scp 到 `/opt/fcmediaagent-staging/server.tar.gz`。
2. 解包到 `app/`，写 `.env`（PORT=3100、DATABASE_URL 指 127.0.0.1:3307、ARK_API_KEY、WECHAT_PAY_MOCK=1、DEV_RETURN_SMS_CODE=true、PACKAGE_VALID_DAYS=30）。
3. `npm install --omit=dev` + `npm i prisma@6.19.2 --no-save` + `npx prisma generate`（远程 Linux 引擎必须自己 generate，不能拷 Windows 的 query_engine）。
4. 迁移与 seed 从本地经 SSH 隧道跑（`ssh -N -L 13307:127.0.0.1:3307`，`DATABASE_URL=mysql://fcm:fcm_staging_pass@127.0.0.1:13307/fcmediaagent_staging`）：
   `prisma migrate deploy` → `tsx prisma/seed.ts`（输出 `[seed] employees: 17`）。
5. `systemctl enable --now fcmediaagent-staging`、`systemctl enable --now fcmediaagent-worker`。
6. 验证：`curl http://127.0.0.1:3100/api/health` → `{"status":"ok","db":"up"}`。

### worker 环境变量（`/opt/fcmediaagent-staging/worker/.env`）

```
FCM_API=http://127.0.0.1:3100/api
FCM_PHONE=13900000002          # dev 短信登录，服务端 DEV_RETURN_SMS_CODE=true 时自动取 devCode
FCM_DEVICE_ID=cloud-staging-1

FCM_MODEL=doubao-seed-2-0-lite
# FCM_REQ_TIMEOUT_MS=180000    # 单请求超时（默认 180s），防止上游挂起把 worker 卡死
```

worker 行为：启动登录 → 30s 心跳 `POST /employee-execution/heartbeat` → 5s 轮询 `POST /employee-execution/pull?limit=1` → 调 `/compute/chat/completions`（非流式）→ 回写 `awaiting_approval`；失败写 `failed` 并把错误留在任务上。

## 4. 实测证据（2026-11-05）

- 节点注册：`GET /employee-execution/nodes` → `cloud-staging-1`，`executor=cloud`，`effectiveStatus=online`，metadata `{host:"staging",runtime:"v22.23.4"}`。
- 端到端：任务 `冒烟：生成一条获客选题`（executor=cloud）→ 08:56:49 claimed → 08:58:59 done，耗时 **130s**（模型实际生成 5081 completion tokens，其中 reasoning 3473）→ 状态 `awaiting_approval`，`outputMeta={executor:"cloud",node:"cloud-staging-1",model:"doubao-seed-2-0-lite",usage:{...}}`，正文为结构化「5 条口腔诊所选题表」（钩子/内容/行动号召/预期线索量）。
- 同一提示词直连火山方舟耗时 42s（1829 tokens）；经本服务端代理耗时 104s（15749 字节，5081 tokens）→ 说明链路本身无额外阻塞，**耗时取决于模型生成长度**（该模型带 reasoning）。
- 失联回收：把 `EMPLOYEE_TASK_STALL_MINUTES=3` 后可复现「running 超时 → 重新排队」，超 2 次转 `failed`（`scripts/smoke-t19.mjs` 覆盖）。

## 6. 边界与注意事项

- **不要**在这台机器上装 Caddy/1Panel 反代、不要改别人的容器；3100 只监听内网可达，对外暴露需另做（后续接域名/HTTPS 时再决定）。
- 磁盘仅剩 2.2G：**不要**在这台机器做 electron-builder 或 npm 全量 devDependencies。
- 内存 2G：API 限制 512MB、worker 256MB；同机还有别的业务，压测前先看 `free -m`。
- 该机是**隔离测试环境**，数据库与本地 `fcmediaagent_v2` 无关；生产库 8.163.59.118 仍只读、未触碰。
- 云端 worker 目前用 dev 短信登录（`DEV_RETURN_SMS_CODE=true`）。正式环境必须换成专用机器账号或 service token。
