# T-11 渠道接入实施方案（企微 / 公众号 / 个人微信）

> 状态：blocked(env) —— 代码骨架可按本文实施，真正跑通需要用户提供凭证与一台常开的 Windows 机器。
> 更新：2026-11-06 dsh-lead

## 0. 一句话结论

三条路线的难度与代价差别很大，**建议顺序：企业微信自建应用 → 公众号（服务号）→ 个人微信（最后做，仅作私域兜底）**。
前两条是官方 API，稳定、不封号；个人微信没有官方 API，只能 UI 自动化（我们现在就是这么做的），一定有封号风险。

---

## 1. 企业微信（推荐先做，1–1.5 人日）

### 走哪条路
| 方式 | 能收消息 | 能主动发 | 需要什么 | 适用 |
|---|---|---|---|---|
| **自建应用**（推荐） | 能 | 能（应用消息，不限量） | corpid + 应用 Secret + AgentId + 回调配置 | 员工在企微里跟 AI 员工对话 |
| 群机器人 webhook | 不能 | 能（群消息） | 只要一个 webhook URL | 只做通知播报，最简单 |
| 客户联系（外部群） | 能 | 能 | 企业认证 + 客户联系权限 + 会话存档（付费） | 私域客户群自动回复 |

首版只做**自建应用 + 群机器人**，客户联系留到有真实需求再说。

### 你要在企微后台做的（约 15 分钟）
1. 企业管理后台 → 我的企业 → 记下 **企业ID（corpid）**。
2. 应用管理 → 自建 → 创建应用「AI 员工」，记下 **AgentId** 与 **Secret**。
3. 应用 → 接收消息 → 设置 API 接收：
   - URL：`https://api.fcmediaagent.com/channels/wecom/callback`
   - Token：自己生成一串随机（如 32 位字母数字）
   - EncodingAESKey：点「随机获取」
   - 把这 3 个值发我（Token 和 AESKey 必须与这里一致）。
4. 应用 → 网页授权及 JS-SDK → 可信域名填 `api.fcmediaagent.com`，按提示下载 `WW_verify_xxxx.txt` 发我（我放到站点根目录做校验）。
5. 应用 → 企业可信 IP：把 `47.85.46.165` 加进去（不加则调用 API 会报 60020）。
6. （可选，通知用）某个群里加「群机器人」，把 webhook URL 发我。

### 我要写的代码（不需要你先给凭证，我可以先用假凭证写）
- `packages/server/src/channels/wecom/`：GET 回调 URL 验签（sha1 排序拼接）、POST 消息 AES-256-CBC 解密 + 验签、被动回复（5 秒内回 XML）、超时转异步用「客服/应用消息」补发。
- 消息路由：企微用户 openid → 平台账号映射（未绑定时回一段绑定链接），命中后转给 `employee-execution` 的云端执行器，产出回发。
- 主动推送：任务完成 / 待审批提醒 → 应用消息。
- 后台「渠道网关」页接真实配置项（corpid/agentid/secret/token/aeskey/webhook），密钥入库前加密（沿用 `scripts/import-secrets.mjs` 的 scrypt 方案）。

### 验收标准
企微里给应用发「帮我看下今天 AI 行业有什么新政策」→ 5 秒内收到「已收到，正在处理」→ 30–120 秒内收到完整结果；后台能看到该次调用的积分流水。

## 2. 微信公众号（服务号，2 人日）

### 前置（很硬）
- **必须是已认证的服务号**（订阅号没有客服消息接口，做不了对话）。
- 需要：**AppID、AppSecret**（公众号后台 → 设置与开发 → 基本配置）。
- 服务器配置（同企微）：URL `https://api.fcmediaagent.com/channels/wechat-mp/callback`、Token、EncodingAESKey（消息加解密方式选**安全模式**）。
- **IP 白名单**：把 `47.85.46.165` 加进「IP 白名单」，否则拿不到 access_token。
- 认证服务号的「网页授权域名」填 `ai.fcmediaagent.com`。

### 已知限制（要提前跟用户对齐）
- **客服消息只能回复 48 小时内互动过的用户**，超过就要用模板消息/订阅通知（需用户授权、有次数限制）。
- 群发一天一次且有内容审核；不适合做高频对话。
- 所以公众号定位应该是「**服务入口 + 低频客服**」，不适合当主对话渠道。

### 我要写的代码
- 签名校验（token/timestamp/nonce/sha1）、安全模式解密（AESKey 43 位 base64 + IV 前 16 字节）。
- 事件处理：subscribe / unsubscribe / TEXT / IMAGE / VOICE。
- access_token 缓存（7200 秒，redis 或进程内 + 提前 5 分钟刷新）、客服消息发送、素材上传。
- 同样路由到员工执行器，长任务先回「正在处理」。

## 3. 个人微信（固定窗口环境，3–5 人日 + 一台常开 Windows 机器）

### 为什么需要「固定窗口」
个人微信没有官方 API，只能靠 Windows UI 自动化（UIAutomation）去点客户端。UIA 要求**微信窗口存在且处于已渲染的交互式桌面会话**：
- 窗口最小化 / 被锁屏 / RDP 断开 → 元素树拿不到，脚本直接失效。
- 微信版本一升级，控件结构就变，脚本全废。

所以要「专用机器 + 锁定版本 + 固定窗口 + 不锁屏」。

### 环境要求（你这边准备）
1. **一台常开的 Windows 10/11 机器或虚拟机**（2C4G 足够），不要用你自己的办公电脑。
2. 装 **微信 PC 3.9.x**（3.9.11 最稳；**绝对不要 4.x**，wxauto 不支持）。
   - 安装后：设置 → 通用 → **关闭「自动更新」**；在 `C:\Program Files (x86)\Tencent\WeChat` 目录设只读，阻止偷偷升级。
3. **专用微信号**（建议小号，别用主号，有封号风险），登录时勾「记住密码」。
4. 系统设置：关闭睡眠/休眠/屏保、关闭 Windows 自动更新重启、**不要锁屏**。
5. 微信窗口：登录后拖到屏幕固定位置、固定大小，**不要最小化**。
6. **RDP 断开会让 UIA 失效** —— 两种解法二选一：
   - 用虚拟机控制台（VMware/Hyper-V console）而不是 RDP；
   - 或用 RDP 时执行 `tscon %sessionname% /dest:console` 把会话切回物理控制台再断开。
7. 这台机器只跑网桥，防火墙只放行我们服务器的 IP；网桥只监听 `127.0.0.1`，通过内网/隧道给服务端访问（或把网桥装在同一台机器上跑反向隧道到 47.85.46.165）。

### 我要写的代码（**已派 teammate 在做**）
`packages/wechat-bridge/`（Python 3.11 + FastAPI + wxauto），实现服务端 `packages/server/src/channels/personal-wechat.service.ts` 需要的 6 个接口：
`GET /api/v1/bot/status`、`GET /api/v1/memory/list`、`GET /api/v1/chat/messages`、`POST /api/v1/chat/send`、`POST /api/v1/chat/send-file`、`POST /api/v1/chat/listen-list`，带 Bearer 鉴权与 Mock 模式（没装微信也能联调）。
服务端侧只需 `.env` 填 `WECHAT_UIA_BASE_URL` + `WECHAT_UIA_TOKEN` 即接通。

### 风控红线
- 单号每日主动发送 **≤200 条**，新号先养 7 天再上量。
- 每条消息随机延迟 0.3–1.2 秒、长文本分段（humanize）。
- **不要同文群发**（同一段文字发给 20 人以上，必触发风控）。
- 只回「私聊/已加入的群」，不做主动加好友、不拉群。
