# P37 平台页「弹出视频号助手」+ 抖音冷启动误报「打开页面失败」

日期：2026-11-10　版本：0.1.21　提交人：dsh-lead

## 一、用户反馈
User（2026-11-10）：**「bug:我点击平台发布,它会弹出视频号助手.」**

## 二、根因（已确证）
- 进入「平台发布」页会立刻查三平台登录态：`packages/desktop/src/renderer/src/pages/PlatformPublish.tsx:89-93` → `window.fcm.platform.warm()` + `status({})`。
- 主进程 `packages/desktop/src/main/platform.ts` 的 `checkStatusFresh(platform)` 里，为了让页面真的渲染，写着：
  ```ts
  if (driver.needsVisibleWindow) win.showInactive()
  ```
- 只有视频号的 driver 配了 `needsVisibleWindow: true`（`packages/desktop/src/main/platform-drivers.ts:141`，原因：视频号页面在隐藏窗口里 wujie 子应用不渲染，body 只剩「视频号 · 助手」）。
- 于是「查登录态」把视频号窗口真的显示出来了 ⇒ 用户看到「弹出视频号助手」。

## 三、修复
1. 新增 `private showForRender(win)`：先 `win.setOpacity(0)`（不支持则退化成普通显示），再 `safeShowInactive(win)` —— 页面处于「可见」状态、wujie 正常渲染，但完全透明。
2. `checkStatusFresh` 里的 `win.showInactive()` 改为 `this.showForRender(win)`。
3. 透明度必须还原：`safeHide` / `closeWindow` 里 hide 后 `setOpacity(1)`；`ensureWindow(platform, show=true)` 在 `show()` 前也 `setOpacity(1)`，否则用户真正点「扫码登录」时窗口是透明的。
4. 排障日志：探测到页面但 `needsVisibleWindow` 且文本 < 200 字时记「页面文本过短（N 字）」。

## 四、顺带修掉的两类误报（抖音最常见的两个）
### 4.1 「登录态检查失败：打开页面失败：ERR_ABORTED」
- 抖音 `/creator-micro/content/upload` 会 302 跳走，`loadURL` 以 ERR_ABORTED 结算；旧逻辑只要见到 aborted 且路径不同就继续等，等到 30s 报错。
- 修法：导航前记 `startHref = win.webContents.getURL()`，就绪判定里加 `const movedOn = !!startHref && last.href !== startHref`，`!aborted || movedOn || samePath(...)` 即算成功（地址变了 ⇒ 是页面自己跳，不是被拦）。
- 对视频号的脏表单 beforeunload 场景仍然判失败：地址没变。

### 4.2 超时终检
- `navigate()` 抛错前做一次 3 秒终检（`READY_SCRIPT`），ready 且 href != about:blank 就当作成功并记 `[navigate] 超时终检发现页面其实已就绪`。

### 4.3 导航失败不再等于登录态检查失败（关键）
- `checkStatus`/`checkStatusFresh`：`await this.navigate(...)` 包 try/catch 记 `navError`，**失败不返回**，继续 probe 页面；
- 导航失败时探测轮次 8 → 15（约 7s → 13s）；
- 探到内容就按 cookie/文案正常判登录态；探不到才报「页面没有响应」；探到内容但判定未登录且 `navError` 非空时，报「页面没有响应（打开超时）」，**不谎报「未登录」**（避免让用户白扫一次码）。

### 4.4 试过又撤回的一招（写下来免得再试）
把查登录态的导航超时砍到 12s（`STATUS_NAV_TIMEOUT_MS`）：真机冷启动实测小红书页面还没渲染完，probe 读到登录墙 ⇒ 误判「未登录」（2026-11-10T07:17）。**已撤回**，保持 30s。
